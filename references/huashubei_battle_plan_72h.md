# 华数杯 72 小时作战时间表（国一标准）

> 华数杯赛制：72 小时（通常周四 18:00 ~ 周日 18:00），3 人一队，中文论文。
> 本表按国一标准设计：选题 2h + 建模 36h + 写作 24h + 终审 10h。
> 加载时机：stage 0 kickoff，当用户选定 huashubei 后立即加载，按小时推进。

---

## 总览：72 小时里程碑

| 阶段 | 时段 | 累计 | 核心产出 | Checkpoint |
|------|------|------|----------|-----------|
| **0 启动+选题** | h0-h4 | 4h | 题目选定 + decision_log | ☐ h4 选题锁定 |
| **1 问题分析** | h4-h8 | 8h | 子问题分解 + 技术路线图 | ☐ h8 路线确定 |
| **2 基础建模** | h8-h20 | 20h | 子问题一/二模型 + 初步结果 | ☐ h20 核心模型跑通 |
| **3 深化求解** | h20-h40 | 40h | 全部子问题求解 + 图表 | ☐ h40 结果完整 |
| **4 稳健性** | h40-h46 | 46h | 灵敏度 + 稳健性 + 评价 | ☐ h46 检验完成 |
| **5 论文写作** | h46-h64 | 64h | 摘要+正文+附录初稿 | ☐ h64 全文成稿 |
| **6 终审打磨** | h64-h72 | 72h | 终审 + 编译 + 提交 | ☐ h72 提交 |

## 详细时间表

### 阶段 0：启动 + 选题（h0-h4，4 小时）🔴 CHECKPOINT

**h0-h1：资料预扫 + 启动**
- [ ] 读取题目 PDF（3 题各读 1 遍，10 分钟/题）。
- [ ] 加载 `competitions/huashubei/winning_patterns.md` 建立基线。
- [ ] 初始化 `cwd/state/decision_log.json`（competition=huashubei）。

**h1-h3：选题决策**
- [ ] 加载 `references/huashubei_topic_decision.md`。
- [ ] 填"三题五维评估表"+"队伍配置表"。
- [ ] 套选题决策矩阵公式，量化打分。
- [ ] 查"一票否决"和"逆向选择"。
- [ ] **3 人一致确认题目**（避免中途换题，72h 换题必败）。

**h3-h4：选题后立即动作**
- [ ] 加载 `competitions/huashubei/distilled_modeling.md` 对应题型章节。
- [ ] 加载 `competitions/huashubei/topic_specs.json` 确认 task_type。
- [ ] 分工：建模 / 编程 / 写作 3 人明确职责。
- [ ] 建立 `cwd/code/`、`cwd/figures/`、`cwd/results/`、`cwd/paper/` 目录。
- [ ] 复制 LaTeX 模板：`templates/latex/huashubei/` → `cwd/paper/`。

**☐ CHECKPOINT h4：选题锁定。写入 decision_log：topic、task_type、分工。此后不换题。**

---

### 阶段 1：问题分析（h4-h8，4 小时）

**h4-h6：深度读题 + 子问题分解**
- [ ] 读题 3 遍，逐字理解每个子问题。
- [ ] 列出所有子问题（通常 3-5 问）。
- [ ] 列出所有附件、字段、约束。
- [ ] 画**全文技术路线图**（mermaid/graphviz）。

**h6-h8：模型候选 + 技术路线确定**
- [ ] 每个子问题按 stage 3 短名单规格定候选（1 主 + 1 baseline + 至多 1 条件性备用，不按族数凑）。
- [ ] 加载 `references/model_catalog.md`。
- [ ] 确定每个子问题的主模型 + 备选模型。
- [ ] 确定算法栈（精确/启发式/数据驱动）。
- [ ] 写"问题分析"章草稿（含技术路线图）。

**☐ CHECKPOINT h8：技术路线确定。3 人对建模路线达成一致。**

---

### 阶段 2：基础建模（h8-h20，12 小时）🔴 关键期

**h8-h12：子问题一建模 + 求解**
- [ ] 建立子问题一模型（A 题写物理方程 / B 题写决策变量目标约束 / C 题做数据清洗+特征）。
- [ ] 编码实现，跑通初步结果。
- [ ] **给模型命名**（国一标志）。
- [ ] 画第一张结果图。

**h12-h16：子问题二建模 + 求解**
- [ ] 在子问题一基础上建立扩展模型。
- [ ] 编码实现，跑通结果。
- [ ] 画结果图。

**h16-h20：子问题三/四建模 + 求解**
- [ ] 同上闭环。

**☐ CHECKPOINT h20：核心模型全部跑通。写入 decision_log：各问模型名、关键结果。**
**⚠️ 若 h20 核心模型未跑通，立即降级——简化模型，保住"有结果"比"模型完美"重要。**

---

### 阶段 3：深化求解（h20-h40，20 小时）

**h20-h28：结果完善 + 多算法对比**
- [ ] 每个子问题至少用 2 种算法求解（互校）。
- [ ] B 题：跑基准函数验证算法（Ackley/Rastrigin）。
- [ ] C 题：K 折交叉验证分类模型。
- [ ] 优化算法参数（网格搜索/手动调）。

**h28-h34：核心图表生成**
- [ ] 加载 `references/huashubei_figure_pack.md`。
- [ ] 按题型生成必要图表；优先覆盖结构、机制、中间状态、结果和可信边界，不追求固定数量。
- [ ] 全文技术路线图、算法流程图、结果图、对比图、灵敏度图。
- [ ] **每张图后写 1-3 句中文解释**。

**h34-h40：结果整理 + 数据表**
- [ ] 整理所有定量结果到表。
- [ ] 确保结果数值一致（子问题间、图表间、结论间）。
- [ ] 附录代码整理可运行。

**☐ CHECKPOINT h40：结果完整。所有子问题有解，图表齐备。**

---

### 阶段 4：稳健性 + 评价（h40-h46，6 小时）

**h40-h43：灵敏度 + 稳健性**
- [ ] 选 2-3 个关键参数，±20% 扰动，画曲线/九联图。
- [ ] 多算法结果对比（精确度差异）。
- [ ] B 题：基准函数收敛对比图。
- [ ] C 题：评价权重灵敏度（权重扰动看排序稳定性）。

**h43-h46：模型评价 + 推广**
- [ ] 写"模型评价"章：优点 / 缺点 / 推广。
- [ ] **诚实报告局限**（国一特征，见 winning_patterns.md 模式 6）。
- [ ] 写收尾升华段（方法论高度）。

**☐ CHECKPOINT h46：检验完成。论文核心技术内容全部就绪。**

---

### 阶段 5：论文写作（h46-h64，18 小时）🔴 写作期

**h46-h50：摘要 + 问题重述 + 问题分析**
- [ ] 加载 `competitions/huashubei/abstract_template.md` + `phrase_bank.md`。
- [ ] 按 abstract_template 五项功能覆盖写摘要（真实模型名 + 定量结果 + 边界句）。
- [ ] **摘要写 3 遍**（h46 初稿 / h60 重写 / h68 终审润色）。
- [ ] 问题重述（背景 + 提出）。
- [ ] 问题分析（含技术路线图）。

**h50-h58：模型建立与求解（核心章，占 60%）**
- [ ] 每个子问题单独闭环：题意 → 模型 → 求解 → 结果 → 解释。
- [ ] 插入图表 + "由图 X 可见…"解释。
- [ ] 公式编号、符号说明。
- [ ] 加载 `competitions/huashubei/distilled_formats.md` 查格式规范。

**h58-h62：稳健性 + 评价 + 参考文献**
- [ ] 灵敏度/稳健性章（h40-h43 的结果）。
- [ ] 模型评价章。
- [ ] **摘要第 2 遍重写**（h60，对照全部图表与定量结果重写）。
- [ ] 参考文献（10-25 篇，中英文混合，优先期刊+国际标准）。

**h62-h64：附录 + 首次编译**
- [ ] 附录代码（有注释，可运行）。
- [ ] 补充图表、大表。
- [ ] **首次 xelatex 编译**，修编译错误。

**☐ CHECKPOINT h64：全文成稿。PDF 可编译。**

---

### 阶段 6：终审打磨（h64-h72，8 小时）🔴 终审期

**h64-h66：终审自检（stage 9）**
- [ ] 加载 `competitions/huashubei/anti_patterns.md`，逐条对照。
- [ ] 加载 `competitions/huashubei/rubric_overlay.json`，6 维度自评。
- [ ] 检查清单：
  - ☐ 摘要每问有定量结果？
  - ☐ 章节按问题推进（非算法堆叠）？
  - ☐ 模型有命名？
  - ☐ 每张图表都有主张、上游数据、必要检查和正文解释？
  - ☐ 坐标轴有名称和单位？
  - ☐ 无"显著优于"无证据夸大？
  - ☐ 结论数值与正文一致？
  - ☐ 参考文献 10-25 篇含期刊和英文？

**h66-h68：摘要终审润色（第 3 遍, h68 收口）**
- [ ] 摘要是定档关键，**单独留 2 小时精修**。
- [ ] 检查：模型命名、定量结果密集、方法链动词、收尾升华。
- [ ] 让写作能力最强的队员独立审摘要。

**h68-h70：Panel 多视角审核**
- [ ] 加载 `rubric_overlay.json` 的 panel_personas。
- [ ] 物理机理派评委视角（A 题）/ 算法工程派（B 题）/ 数据洞察派（C 题）/ 写作派。
- [ ] 逐视角找问题，定向修复。

**h70-h71：最终编译 + 排版**
- [ ] 最终 xelatex 编译（编译 2 遍确保目录正确）。
- [ ] 检查 PDF：字体嵌入、图片清晰、页码、交叉引用无 "??"。
- [ ] 总页数 20-50 页（正文+附录）。

**h71-h72：提交**
- [ ] 确认提交要求（PDF 格式、命名规范、提交平台）。
- [ ] **留 1 小时缓冲**（应对网络/平台问题）。
- [ ] 提交，确认成功。

**☐ CHECKPOINT h72：提交完成。**

## 72h 红线（不可触碰）

1. **h4 后不换题**：换题 = 72h 浪费前 4h + 重新建模，必败。
2. **h20 核心模型必须跑通**：跑不通立即降级简化，"有结果" > "模型完美"。
3. **h46 后不新增模型**：剩余时间用于写作和打磨，不再开新坑。
4. **h64 必须有可编译 PDF**：留 8h 终审，不能压到最后。
5. **摘要写 3 遍**：h46 初稿 / h60 精修 / h68 终审，定档关键。

## 三人分工建议

| 角色 | h0-h20 | h20-h40 | h40-h64 | h64-h72 |
|------|--------|---------|---------|---------|
| **建模手** | 主导建模、推导方程 | 完善模型、灵敏度设计 | 写模型建立章 | 审模型严谨性 |
| **编程手** | 编码实现、跑结果 | 多算法对比、图表生成 | 写求解章+附录代码 | 审代码可复现性 |
| **写作手** | 读题、列大纲 | 整理结果表 | **主导写作**、摘要 | 主导终审、排版、提交 |

**关键**：写作手 h40 后全职写作，不再碰代码。建模手和编程手 h46 后转入辅助写作 + 审稿。

---

## 应急预案

| 状况 | 应对 |
|------|------|
| h20 模型跑不通 | 立即降级：简化假设、减少变量、用近似算法。保"有结果"。 |
| h40 结果不全 | 砍掉最不重要的子问细节，保核心子问完整。 |
| 编译失败 | 定位首个报错，优先修模板变量/图片路径/中文编译器。 |
| 队员状态差 | 写作手顶上建模/编程的文档部分；保证摘要+核心章质量。 |
| 时间不够 | 优先级：摘要 > 核心子问建模 > 图表 > 稳健性 > 附录。 |
