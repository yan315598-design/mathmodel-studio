## 常见翻车案例（前车之鉴, 终检时逐条回想）

| 案例 | 后果 | 预防 |
|---|---|---|
| PDF 在评委机器打不开（字体未嵌入） | 直接废稿 | 终检 3: 换机器/手机打开验证; xelatex 编译默认嵌字体, pdflatex 需检查 |
| 文件名含空格/中文导致系统截断 | 上传失败或乱码 | 终检 2: 重命名为 ASCII 安全名 |
| 附录代码压缩包解压后路径断裂跑不通 | 支撑材料形同虚设 | 终检 8: 解压到干净目录空跑一遍 |
| 提交后没截图, 系统后来出问题无法自证 | 无法申诉 | 终检 10: 回执截图是唯一凭证 |

## 通用终检 10 条（所有竞赛提交前过一遍）

| # | 检查项 | 说明 |
|---|---|---|
| 1 | 页数上限 | 对照本竞赛页数要求（mcm 25 页硬上限; 中文赛按通知） |
| 2 | 文件名规范 | 含队号/竞赛前缀, 无中文空格乱码（按当年通知） |
| 3 | PDF 可打开 | 双击打开、翻页正常、字体不缺、图不糊 |
| 4 | 图表编号连续 | 图/表/公式编号无跳号无重复 |
| 5 | 无重复 caption | 同名图注/表注清零（编译两遍 LaTeX 让引用正确） |
| 6 | 匿名性 | 按竞赛要求核对正文/页眉/图例/代码注释里的身份信息 |
| 7 | 摘要独立成页 | 中文赛首页摘要独立; mcm 为 Summary Sheet |
| 8 | 代码附件可读 | 支撑材料里的代码可解压、注释齐全、入口命令写在 README |
| 9 | 备份三处 | 本地 + 移动介质/网盘 + git 提交, zip 的 MD5 记录 |
| 10 | 提交后截图留证 | 系统回执/邮件发送成功页面截图存档 |

## 提交目录结构与当日时间线

`scripts/package_submission.py --apply` 产出的标准布局:

```
<workspace>/submission/
  <comp>_<timestamp>.zip     # 论文 PDF + code/ + README
  backup/<comp>_<timestamp>.zip
```

提交当日（按 DDL 倒排, 与 Stage 9"最后 6 小时"路径衔接）:

| 时点 | 动作 |
|---|---|
| T-2h | 终稿编译 → 跑通用终检 10 条 → `package_submission.py` dry-run |
| T-1h | `--apply` 打包 + 核对 zip 内容清单 + 备份三处 |
| T-30min | 登录提交系统上传; 大附件先测网络; 保留失败重传余地 |
| T-0 | 提交成功截图（回执号/时间戳）存 `submission/` |
| T+5min | 核对系统内文件可下载、页数正确; 此后才算提交完成 |

## 与脚本的配合

```bash
# 预览检查（dry-run, 不打包）
python <skill>/scripts/package_submission.py
# 实际打包: zip 到 cwd/submission/<comp>_<timestamp>.zip 并备份
python <skill>/scripts/package_submission.py --apply
```

脚本覆盖通用项 1/2/3/8 的可自动化部分与打包备份; 承诺书/匿名性/摘要独立成页等语义项由 agent 按本清单人工核对, 脚本只做存在性提示。
