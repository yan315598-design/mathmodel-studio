# 文献获取桥接 (reference skills)

> 0.7.4 新增：把"文献检索"从顺手行为变成有硬上限、有信源分级、有真实性核验的受控流程, 并桥接环境里已安装的文献类 skill。

---

## 挂接点

| 时机 | 动作 | 输出 |
|---|---|---|
| Stage 2 题面解析后 | 从题面关键词生成中英文检索词, **≤5 组**（中文 2-3 组 + 英文 2 组） | 检索词清单写入 `decision_log.stages.2` |
| Stage 8 写作期 | 按引用缺口补查（某方法依据/数据背景缺文献支撑时） | 补查记录 + 新增引用条目 |

其他阶段不触发文献检索; Stage 3 选模型需要文献佐证时, 复用 Stage 2 已得文献, 不重复搜索。

### 检索词生成（Stage 2 实操示例）

从题面关键词按"对象 + 方法 + 约束"三要素组词, 中文词与英文术语对齐:

| # | 中文检索词 | 英文检索词 | 目的信源 |
|---|---|---|---|
| 1 | 【对象】+【核心指标】+ 优化 | 【object】+【indicator】+ optimization | T1 期刊 |
| 2 | 【核心方法】+ 适用性（如 "熵权法 TOPSIS 适用条件"） | 【method】+ applicability / comparison | T1 期刊 |
| 3 | 【数据背景】+ 统计特征（如 "共享单车 需求 时空分布"） | 【domain】+ spatiotemporal demand | T1/T2 |
| 4 | 【改进策略】+ 【基准】（如 "机会约束 预算 求解"） | chance-constrained + budget | T1 |
| 5 | （备用, 仅当 1-4 不足）教材/标准词（如 "多目标规划 教材"） | — | T3 |

规则: 每组检索词先想清楚要支撑论文里哪一处引用点（方法依据/参数取值/数据背景）, 想不清楚的不搜。

---

## 硬上限（纪律, 不是建议）

1. **每阶段 ≤5 次搜索**。搜完 5 次仍不够, 停下来向用户报告缺口, 不自行加搜。
2. **找到 5-8 篇即停**。数模论文引用构成要求（见下）通常 10-15 篇即可满足, 多余的搜索是浪费。
3. **级联回退（T1 搜不到降 T2/T3）仅在用户明确要求时执行**, 默认不自动降级凑数。
4. 够用即停: 引用构成要求满足后, 即使搜索次数未用完也停止。

### 引用构成要求（沿用 stage_08_writing.md §8）

- 总数 ≥10 条
- ≥4 条中文期刊
- ≥3 条英文期刊
- ≥1 条教材或工具书

## 信源分级路由

| 级别 | 信源 | 定位 |
|---|---|---|
| T1 | CNKI 核心期刊 / SCI 期刊 | 方法依据与模型选择的首选 |
| T2 | 学位论文 / 会议论文 | 补充细节与工程实现, 适量 |
| T3 | 教材 / 国家标准 / 官方统计年鉴 | 定义、常数、标准数据的出处 |

路由顺序: 先 T1 后 T2; T3 用于教材引用（构成要求里的 ≥1 条）和数据出处, 不用于方法核心依据。警惕撤稿论文和 predatory 期刊（列名可查 Beall's List 类公开名单）, 命中即弃用。

## 已安装 skill 桥接表

| Skill | 用途 | 调用时机 |
|---|---|---|
| `cnki-search` | CNKI 综合检索 | Stage 2 中文检索词首选入口 |
| `cnki-journal-search` | 按期刊定向检索 | 需要锁定核心期刊（T1）时 |
| `gs-search` | Google Scholar 英文检索 | 英文检索词入口 |
| `gs-cited-by` | 查施引文献 | 判断某方法影响力/找最新进展 |
| `nature-citation` | 引用格式化 | 生成/规范单条引用格式 |
| `reference-manager` | 文献库管理 | 多轮检索后整理去重 |

调用规则:

1. **用户的 harness 有对应 skill 才用**; 没有（或调用失败）则人工检索流程: 主 agent 用 WebSearch/WebFetch 检索, 用户手动下载原文, agent 只负责核验四要素与格式。
2. 每次调用前先声明本次是第几次搜索（对照硬上限）, 调用后登记进 decision_log。
3. 检索词从题面关键词派生（中文词 + 对齐英文术语）, 不凭空造词。

## 真实性硬规

1. **每条文献必须可核验**: 题名 + 作者 + 期刊/出版社 + 年份四要素齐全, 缺一不进文献表。
2. **禁止编造**。agent 不确定某文献是否存在时, 标记 `[待核验]`, 且 `[待核验]` 条目**不进终稿**——终稿前未核验则直接删除并重新补查。
3. 不引用无法获取原文的条目（只见过标题没见过正文的不作为方法依据）。
4. 数据类引用必须给出处（统计年鉴/官方数据/附件数据）, 附件数据不算文献。

### 核验清单（每条文献过一遍）

| 项 | 标准 |
|---|---|
| 四要素 | 题名/作者/期刊/年份齐全 |
| 可获取 | 原文 PDF 或可信网页可打开 |
| 未撤稿 | 期刊正常在刊, 论文不在撤稿名单 |
| 相关性 | 支撑论文中某一处具体引用点 |

## 文献登记（decision_log 片段）

每轮检索后登记, 供 trace_claims 与 Stage 8 复用:

```json
{
  "stage": 2,
  "search_log": [
    {"query": "共享单车 需求 时空分布", "engine": "cnki-search", "results_kept": 3, "search_no": 1}
  ],
  "references": [
    {
      "id": "ref_01",
      "title": "……", "authors": "……", "venue": "系统工程学报", "year": 2023,
      "tier": "T1", "verified": true, "supports": "§5.1 方法依据",
      "gbt7714": "[1] ……",
      "file": "papers/ref_01.pdf"
    }
  ],
  "budget": {"searches_used": 2, "searches_cap": 5, "target_count": "5-8 篇即停"}
}
```

`verified=false` 的条目即 `[待核验]`, Stage 8 引用前必须清零。

## 引用闭环

1. **正文引用与文献表一一对应**: 正文 `[n]` 标记的每条都在文献表中, 文献表每条都在正文被引用 ≥1 次。单端悬空 = 修掉。
2. 引用点写入图表/证据计划（`generate_paper_plan.py` 生成的 evidence ledger）, 每个方法选择主张能指回文献或附件数据。
3. 闭环由脚本复核:

```bash
python <skill>/scripts/trace_claims.py --input state/paper_plan.json --strict
python <skill>/scripts/pdf_qa.py paper_output/main.pdf --anonymous --competition <comp>
python <skill>/scripts/package_submission.py --competition <comp>   # dry-run; 加 --apply 实际打包
```

`abstract_gate != pass` 时不得定稿摘要（沿用 stage_08 规则）。

## 常见情形处置

| 情形 | 处置 |
|---|---|
| T1 搜不到（新兴交叉主题） | 报告用户"T1 无命中", 请示是否降 T2; 默认停 |
| 命中过多（>50 条） | 收窄检索词（加约束词/限定核心期刊）, 不逐条浏览 |
| 时间紧张（赛中 <30 min 可用） | 只补缺口最大的 1-2 条, 其余用教材/标准顶格 |
| 引用构成差 1 条英文 | 从已读方法的原作者线索定向查（gs-cited-by）, 不开新话题搜索 |

## 期刊含金量分级

> 0.7.5 新增。T1/T2/T3 是信源**类别**路由, 本节是期刊**含金量**分档——同为 T1 期刊, 分量可以差一档; 引用 10 条全落在低档会拉低文献观感。分档只影响"优先引谁", 不改变硬上限与真实性硬规。

### 英文四档

| 档 | 代表 | 定位 |
|---|---|---|
| 顶刊 | Nature / Science / PNAS 及各学科旗舰（Lancet、Cell 级） | 领域共识级依据; 数模论文引用 1 条即够分量, 不堆 |
| 权威 | Q1-Q2: IEEE Trans 系列、Operations Research、SIAM 系列、Water Research 等 | 方法依据首选; 数学建模方法出处的主战场 |
| 主流 | Q2-Q3 专业刊 | 常规方法细节、应用案例的补充出处 |
| 慎用 | Q4 / 开放获取浑水刊 / 会议文集 | 仅作背景信息; 与 Beall's List 类名单命中重叠的按信源分级规则弃用 |

### 中文四档

| 档 | 代表 | 定位 |
|---|---|---|
| 一级学报 | 数学学报、系统工程理论与实践、管理科学学报、自动化学报等 | 中文方法依据最高档 |
| EI 中文刊 | 被 EI 收录的中文期刊 | 方法与应用依据的可靠补充 |
| 北大核心 | 北大核心目录内期刊 | 数模论文中文引用的主力盘 |
| 慎用 | 非核心普刊 | 只作数据/背景出处, 不作方法依据 |

### 快速判断法（≤2 分钟/刊）

| 手段 | 操作 | 说明 |
|---|---|---|
| GS h5-index | Google Scholar 期刊页看 h5-index, 同领域横向比 | 英文刊分档最省事的量化依据 |
| 知网标注 | 期刊详情页看"北大核心/CSCD/EI"标注 | 中文刊分档主依据 |
| LetPub | 查期刊分区（JCR Q1-Q4）与预警名单 | 英文刊分区 + 排雷一举两得 |

规则: 分档结果写进文献登记的 `tier` 备注（如 `T1-Q1`）, Stage 8 挑引用时**同等方法依据优先高档**; 不为凑档数引用读不懂的顶刊。

## 参数溯源

> 0.7.5 新增。论文里每个**不是从题目数据拟合出来**的参数, 都必须有出处; 无出处的参数值是评委问"这个数哪来的"时的最大失分点。

### 参数四分类与文内标注句式

| 类 | 定义 | 例 | 文内标注句式 |
|---|---|---|---|
| 物理常数 | 有公认精确值或约定值 | 重力加速度 g=9.8 m/s²、水的密度 | "g = 9.8 m/s²（标准重力加速度, 取常值）" |
| 领域经验值 | 学科文献给出的典型取值/区间 | 设备效率 η=0.85、折旧年限 | "η = 0.85（来源: 文献 [n] 中同类设备实测区间 0.80-0.90 的中值）" |
| 超参数 | 我方为算法/模型性能设定的 | 种群规模 50、迭代 200 次 | "种群规模取 50（经 20/50/100 对比实验选定, 见 §x 图 y）"——写自己的实验, 不冒充文献值 |
| 经济社会参数 | 统计口径的社会经济量 | 人均收入、利率、人口增长率 | "2023 年该市人均可支配收入 x 元（来源: 市统计年鉴 [n]）" |

标注句式统一骨架: **`参数 = 数值（来源: ……）`**, 括号里写文献编号 / 题目附件 / 自家实验三者之一; 类别不同只换括号内容。

### 红线

1. **无题目数据支撑且无文献出处的参数值, 一律标 `[待核验]`, 不进终稿**——与真实性硬规的 `[待核验]` 条目同规则同处置: 终稿前补上出处, 补不上就换成有出处的值或改由数据标定。
2. 超参数不得伪托文献: 自己调出来的值标自家对比实验, 引文献装门面属造假。
3. 题目附件拟合/标定出的参数不算本节管辖（那是数据产物, 走真源结果登记表）, 但文内要写清标定方法。
4. Stage 8 成稿后按本节表逐参数过一遍: 每个非拟合参数都能指到文献 [n] / 附件 / 自家实验之一, 三者皆无即红线命中。
