# 文献获取与引用桥接

本页负责来源获取、真实性核验、参数出处和引用闭环。检索预算、缓存及按缺口继续/停止的唯一规则来源是 `references/literature_scout.md`；中文、英文和写作补查使用同一profile，不另设次数、篇数、语种或刊物等级配额。赛事当年有明确要求时按要求执行。

## 何时检索

Stage 2补背景与概念，Stage 3解决模型机制、反例和实现缺口，Stage 5按失败证据定向查替代，Stage 8补真实引用缺口。先查已有搜索记录，不为阶段切换重复搜索；也不因Stage 2已有几篇就禁止Stage 3继续发现。

检索词围绕对象、机理、约束或失效场景；每轮说明要解决的缺口，并把有用来源转成候选、前提或验证动作。检索数量不是研究充分性的证据。

## 来源与工具

优先直接的方法原文、可信数据发布者和可核验实现。期刊、会议、预印本、学位论文、教材、标准和官方统计各有用途；按主张与内容选择，不按来源类别一律排除方法依据，不把被引量当质量或JCR分区。

宿主已提供且任务确有需要时，可用 `cnki-search` / `cnki-journal-search` 查询中文文献，`gs-search` / `gs-cited-by` 查询英文来源及后续研究，`reference-manager` 去重，`nature-citation` 辅助格式化。没有对应skill就用宿主已有检索/读取工具或本地材料；工具名称不是保证存在的接口。公开可获取全文可由Agent读取，访问受限则标记缺口，不自动要求用户代做可执行工作。

## 核验与登记

- 核验题名、作者、期刊或出版社、年份以及适用的DOI/URL；未知信息如实记录，不编造。未核验条目不进正式文献表。
- 方法依据应读到支撑主张的正文及必要公式/实验条件；仅有元数据或摘要可用于发现，不能冒充机制已审读。不同来源互相矛盾时保留差异。
- 检查来源可信性、修订与撤稿信息；API字段只能证明其覆盖范围。预印本标注版本与身份，不声称已经同行评审。
- 复用现有文献登记、方法卡和证据账本，记录出处、阅读范围、支持的主张以及结果路径；不新建重复文献库。状态含义按Stage 3四轴证据，不用单一verified代表全部工作。

## 参数溯源

参数区分物理常数、领域经验值、题面/数据标定值、算法超参数和情景假设。分别给真实出处、标定过程、训练侧选择依据或假设理由及敏感性；合理但未经实测的情景值可以明确作为假设，不能伪装成测量或文献值。算法默认值可以声明为默认，不编造调参实验。

## 引用闭环与格式

正文引用与文献表对应，每条引用支持具体主张。数据源、题目附件与学术文献按实际身份标注，不为凑篇数混用。引用核验不替代结果语义核验。

中文赛通常使用GB/T 7714，最终服从当年赛事要求。已有竞赛格式参考：`competitions/<comp>/distilled_formats.md`（huaweibei / huashubei / apmcm）；cumcm见 `references/cn_presentation_spec.md`，其他分支按当年通知。MCM按当年要求；外部格式化skill不能覆盖赛事规范。

闭环脚本按实际输出链调用：

```bash
python <skill>/scripts/trace_claims.py --input state/paper_plan.json --strict
python <skill>/scripts/pdf_qa.py paper_output/main.pdf --anonymous --competition <comp>
python <skill>/scripts/package_submission.py --competition <comp>
```

最后一条默认dry-run，实际打包按其`--apply`接口。工具只检查所实现的链条；缺正文、未读原文或科学依据不足不能靠脚本通过补齐。
