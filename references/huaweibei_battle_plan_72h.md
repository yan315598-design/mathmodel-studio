## 详细时间表

### 阶段 0：启动 + 选题（h0-h4，4 小时）🔴 CHECKPOINT

**h0-h1：资料预扫 + 启动**
- [ ] 读题目（A-F 各快读 1 遍，研究生赛题面长，15 分钟/题）。
- [ ] 案例检索预热：`retrieve_cases.py --competition huaweibei --query "<领域词>"`。
- [ ] 初始化 `cwd/state/decision_log.json`（competition=huaweibei）。
- [ ] 工作区按 `workspace_protocol.md` §1：骨架 + `真源.md` 落盘；检测同竞赛旧工作区，有则给编号菜单先归档。

**h1-h3：选题决策**
- [ ] A-F 按题面动态分类题型，**不从字母推断**（每年映射不同）。
- [ ] 加载 `competitions/huaweibei/winning_patterns.md` + `topic_specs.json` 建立基线。
- [ ] 填"多题五维评估表"（题目数多于华数杯，可先粗筛 6→3 再细评）。
- [ ] 套选题决策矩阵量化打分；查"一票否决"与"逆向选择"。
- [ ] **用户确认题目**（单人+AI 模式下用户是决策者，见文末分工表）。

**h3-h4：选题后立即动作 + 口径冻结单**
- [ ] 加载 `competitions/huaweibei/distilled_modeling.md` 对应题型章节。
- [ ] 分工确认（单人+AI：用户=审查/决策，AI=执行）。
- [ ] **口径冻结单**（`workspace_protocol.md` §2）：时间轴 / 指标定义 / 方案命名，逐条标 FACT/CHOICE，写入真源.md——此后所有分析共用同一口径。

**☐ CHECKPOINT h4：选题锁定 + 口径冻结单 v1。写入 decision_log：topic、task_type、分工。此后不换题。**

### 阶段 1：路线 + 图表规格（h4-h8，4 小时）

**h4-h6：深度读题 + 子问题分解**
- [ ] 读题 3 遍，逐字理解每个子问（子问多，先列全清单再排依赖）。
- [ ] 附件 schema 扫描（pandas 扫全量附件）。
- [ ] 画**全文技术路线图**（mermaid/graphviz）。
- [ ] 子问依赖图：哪些子问复用前面结果。

**h6-h8：模型候选 + 图表规格定稿（h24 前可修订）**
- [ ] 每个子问 ≥3 候选模型，加载 `references/model_catalog.md`。
- [ ] 检索相似案例支撑选型：`retrieve_cases.py --competition huaweibei --level question --query "<子问关键词>"`。
- [ ] **图表规格定稿**（`workspace_protocol.md` §2/§5，`stage_02_analysis.md` 图表规格冻结节；h24 前可修订，h24 起硬冻结）：
  - 每问张数预算（多子问题赛制总量 10-20 张起步）。
  - 每图登记四要素：回答什么问题 / 数据源 / 色板（`templates/figures/style/palettes.py` 八套之一，含 1.1.0 期刊板 npg/aaas/lancet/nejm；规则见 `references/color_typology.md`）/ 过程图或结果图。
  - 信息密度标准：**每图 ≥2 个信息维度，过程图:结果图 ≈ 1:2**（华数杯教训：初版一图 2-3 条线信息密度过低，一天返工 5 轮）。
- [ ] 写入真源.md 图表登记表。

**☐ CHECKPOINT h8：技术路线 + 图表规格定稿（可修订）。h24 起硬冻结，此后变更须在真源登记（`workspace_protocol.md` §5）。**

---

### 阶段 2：基础建模（h8-h20，12 小时）🔴 关键期

**h8-h12：子问题一/二建模 + 求解**
- [ ] 建模 + 编码 + 跑通初步结果。
- [ ] **给模型命名**（诚实命名，不冒充未用的方法，见真源"模型命名与诚实声明"）。
- [ ] 按图表规格出第一张图（规格外的图不画）。

**h12-h16：子问题三/四建模 + 求解**
- [ ] 同上闭环；复用前问结果时在真源登记复用关系。

**h16-h20：剩余子问 + 收尾**
- [ ] 全部核心子问有初步解。
- [ ] **真源结果登记表即时登记**：每跑出一个数，立即登记"key/数值/生成脚本/时间戳"，不积压到写作期。

**☐ CHECKPOINT h20：核心模型全部跑通，结果登记表已开始滚动。**
**⚠️ 若 h20 核心模型未跑通，立即降级——简化模型，保住"有结果"比"模型完美"重要。**

---

### 阶段 3：深化求解（h20-h40，20 小时）

**h20-h28：结果完善 + 多算法互校**
- [ ] 每个子问题至少 2 种算法求解（互校）。
- [ ] 优化类跑基准函数验证；预测类做交叉验证。
- [ ] 参数调优（网格/手动）。

**h28-h34：按规格出图**
- [ ] 严格按 h8 冻结的图表规格生成，新增图先补登记再画。
- [ ] **每张图后写 1-3 句中文解释**（"由图 X 可见…"）。
- [ ] 色板统一从 `palettes.py` 取，灰度可分（`grayscale_check`）。

**h34-h40：结果整理 + 每问单项审计**
- [ ] 定量结果整理进真源结果登记表。
- [ ] **每问完成即跑单项审计，不等总审**：`scripts/trace_claims.py --strict`（证据链）+ `scripts/score_artifact.py`（打分），通过与否记入真源修订记录。
- [ ] 子问题间、图表间、结论间数值一致性核对（对真源，不对记忆）。

**☐ CHECKPOINT h40：结果完整。所有子问题有解、图表齐备、每问有单项审计记录。**

---

### 阶段 4：稳健性 + 模型硬冻结（h40-h48，8 小时）

**h40-h44：灵敏度 + 稳健性**
- [ ] 选 2-3 个关键参数 ±20% 扰动，画曲线/九联图。
- [ ] 多算法结果对比；评价权重扰动看排序稳定性（评价类）。

**h44-h46：模型评价 + 推广**
- [ ] 写"模型评价"章素材：优点 / 缺点 / 推广。
- [ ] **诚实报告局限**（负面结果按真源诚实声明如实写入）。

**h46-h48：摘要第 1 遍 + 模型硬冻结**
- [ ] **摘要初稿定主线**（摘要三遍制第 1 遍，与 `stage_08_writing.md` 口径一致：6 句式 问题→方法→关键结果→验证→结论，不写定量细节）。
- [ ] **h48 模型主结构硬冻结**（`workspace_protocol.md` §5）：之后只修 bug 与补灵敏度；推翻须用户编号菜单确认 + 真源登记。

**☐ CHECKPOINT h48：模型主结构冻结。真源修订记录登记冻结行。**

### 阶段 5：论文写作（h48-h64，16 小时）🔴 写作期

**h48-h52：问题重述 + 问题分析**
- [ ] 加载 `competitions/huaweibei/abstract_template.md` + `phrase_bank.md`。
- [ ] 问题重述（背景 + 提出）；问题分析（含技术路线图）。

**h52-h58：模型建立与求解（核心章，占 60%）**
- [ ] 每个子问题单独闭环：题意 → 模型 → 求解 → 结果 → 解释。
- [ ] 按逐问"方法—结果—验证"闭环写（华为杯评审看重逐问证据链）。
- [ ] 插图 + 解释；公式编号、符号说明（对照真源符号表）。

**h58-h60：摘要第 2 遍（结果完成后重写）**
- [ ] 按证据账本逐问重写，每个数字可追踪到真源结果登记表。
- [ ] 以 `scripts/trace_claims.py --strict` 通过为定稿前提。

**h60 起：数字注入，只写不建模**
- [ ] 论文数字一律由脚本从 `results/` 注入（`workspace_protocol.md` §6 的 inject_numbers.py 思路），**禁止手抄**。
- [ ] h60 后不再改模型/重算（发现模型问题须用户确认才动）。

**h60-h64：稳健性章 + 参考文献 + 附录 + 首次编译**
- [ ] 灵敏度/稳健性章（h40-h44 结果，数字同样注入）。
- [ ] 参考文献（中英文混合，优先期刊+国际标准）。
- [ ] 附录代码（可运行、有注释）；**首次 xelatex 编译**修错。

**☐ CHECKPOINT h64：全文成稿，PDF 可编译，数字全部来自注入。**

### 阶段 6：终审 + 打包 + 提交（h64-h72，8 小时）🔴 终审期

**h64-h66：独立验收（三选二）**
- [ ] 按 `workspace_protocol.md` §7 执行：脚本审计输出 + 用户/非产出方复核 + checklist 逐条打钩，**三选二**。
- [ ] 加载 `competitions/huaweibei/anti_patterns.md` 逐条对照；`rubric_overlay.json` 6 维度自评（自评仅作参考，放行靠三选二）。
- [ ] **产出方自评一律视为待验证**，不得作为"可以提交"的依据。

**h66-h68：Panel 多视角 + 摘要第 3 遍**
- [ ] 加载 `rubric_overlay.json` 的 panel_personas，逐视角找问题定向修复。
- [ ] **摘要终审润色**（三遍制第 3 遍，h68）：只改表达不改数据；模型命名、定量结果密集、收尾升华逐项过。

**h68-h70：按清单打包**
- [ ] 对照 `references/submission_checklists.md` huaweibei 节逐项核对（标注 [以当年通知为准] 的条目查当年通知）。
- [ ] `python <skill>/scripts/package_submission.py`（dry-run）→ `--apply` 打包，zip 带时间戳进 `submission/`，备份三处。
- [ ] 最终编译 2 遍；检查字体嵌入、图片清晰、交叉引用无 "??"。

**h70-h72：提交 + 缓冲**
- [ ] 确认提交要求（PDF 格式、命名含队号、提交平台）[以当年通知为准]。
- [ ] **留 ≥1h 缓冲**（网络/平台问题）；提交后截图回执留证。

**☐ CHECKPOINT h72：提交完成。**

## 72h 红线（不可触碰）

1. **禁止另开工作区**：一题一目录，旧工作区先移 `_archive/`（`workspace_protocol.md` §1；历史实战多工作区互串教训）。
2. **禁止文件名后缀修订链**：版本语义只在真源修订记录（§3；历史实战版本失控教训）。
3. **禁止手抄数字进论文**：h60 起一律脚本注入（§6；历史实战手抄数字失真教训）。
4. **禁止产出方自证验收**：结论须独立验收三选二（§7；历史实战自证翻车教训）。
5. **禁止 48h 后静默推翻模型**：推翻须用户编号菜单确认 + 真源登记（§5）。
6. h4 后不换题；h20 核心模型必须跑通（跑不通立即降级简化）。

## 单人 + AI 分工表

| 时段 | 用户（审查者 / 决策者） | AI（执行者） |
|------|----------------------|--------------|
| h0-h8 | 选题目；确认口径冻结单与图表规格 | 读题 / 案例检索 / 分解 / 路线 / 规格起草 |
| h8-h40 | 审查每问结果与单项审计；决策降级 | 建模 / 编码 / 出图 / 真源登记 / 跑审计 |
| h40-h64 | 审查摘要；裁决模型冻结后的推翻请求 | 灵敏度 / 写作 / 数字注入 / 编译 |
| h64-h72 | **独立审查**（终检兜底） | 打包 / 清单核对 / 回执留证 |

**案例依据**：历史实战中，审计报告宣称"已具国一水平"，用户独立审查却发现多项根本性风险——用户独立审查是最后兜底，不可省。

## 应急预案

| 状况 | 应对 |
|------|------|
| 会话中断 / 新会话 | 走 `workspace_protocol.md` §4 三步：读 decision_log → 读真源口径冻结单与修订记录末尾 → 报告当前阶段/已冻结/待办 3 条 |
| token 超支降级 | 砍检索与 panel 轮次；保真源登记、单项审计、摘要三遍、数字注入；结果全部落盘文件，不依赖上下文记忆 |
| solver 失败 | 按求解器链换（GLPK_MI → HIGHS → SCIP，见 `stage_preseason.md` §① 冒烟脚本）；再失败降级模型（松弛/启发式） |
| LaTeX 模板编译失败 | 按 `stage_preseason.md` §② 的 5 套已知 bug 模板绕过表处理；huaweibei 模板以本机兵检实测为准 |
| h20 模型跑不通 | 立即降级：简化假设、减变量、近似算法，保"有结果" |
| 时间不够 | 优先级：摘要 > 核心子问建模 > 图表（按规格）> 稳健性 > 附录 |
