# 子 Agent 并行调度协议

> v7.4.0 新增：定义 mathmodel-studio 在哪些阶段可以派子 agent 并行、怎么写 prompt、怎么合并、预算耗尽怎么办。Stage 9 的 5 视角 panel 沿用 `references/feedback_layer3_panel.md`, 本文不重复定义。

---

## 总则

1. **独立 context 防锚定**: 每个并行子任务在独立 context 里跑, 子 agent 之间不共享中间稿, 防止互相锚定导致输出同质化。
2. **prompt 自包含**: 每个并行任务的 prompt 必须含文件路径、任务规格、验收标准, 子 agent 没有主对话记忆。
3. **主 agent 做合并**: 子 agent 只交付工件（结构化提取/求解包/章节草稿）, 合并与一致性回检永远由主 agent 做。
4. **写锁纪律**: 并行开始前必须冻结共享表（符号表/假设表/术语表）, 冻结期间子 agent 只读不写; 需要改共享表的任务不并行。
5. **用户文件不可覆盖**: 子 agent 对用户已有文件只允许 patch 或写新文件; 覆盖前必须先备份（`<file>.bak` 或 git commit）。

### harness 映射

| Harness | 并行机制 | 说明 |
|---|---|---|
| Claude Code | `Agent` 工具, 同一条消息发多个 subagent 调用 | 与 `references/harness_compat.md` 的 panel 并行模式一致 |
| Codex CLI | 多个独立子任务; 无子任务能力时串行 | 见 harness_compat: "5 个独立 codex 子任务 (或串行)" |
| ZCode | Agent 工具（协调者派子 agent） | 主 agent 用协调者身份派发, 结果经 `RespondToCoordinator` 回流 |

### 子 Agent 花名册 (v1.0.0)

全程可派的 8 类角色。每个角色固定输入/输出契约，prompt 自包含；所有角色只交付工件，合并与决策权在主 agent/用户：

| 角色 | 阶段 | 输入 | 输出 | 关键纪律 |
|---|---|---|---|---|
| 题面提取员 | 1 | 单题题面+提取字段表 | 结构化 JSON | 不下结论，只提取 |
| 审题质询员（红队） | 2 | 题面+三查清单（不含主 agent 结论） | 找茬清单（边界漏项/目标误读/假设过强/子问遗漏） | 独立 context，防结论污染 |
| 文献核验员 | 2/8 | 检索词+候选文献清单 | 四要素核验结果+级别标注 | 找不到的文献标 [待核验]，不编造 |
| 子问求解员 | 5 | 单问求解包（冻结符号/假设表+数据路径） | results/Qi_* 扁平命名产物 | 只读共享表 |
| 代码审计员 | 5/6 | 求解脚本+运行清单 | 审计报告（退出码/数值范围/约束违反） | 亲自重跑，不信转述 |
| 章节起草员 | 8 | 单节写作包（frozen 数字+证据账本节选） | 单节草稿 | 数字只用 frozen，不引入新数 |
| 一致性审计员 | 8/9 | paper_workspace + frozen_numbers.json | `scripts/consistency_audit.py` 报告+人工判读 | 只报不修 |
| 评委席位 ×N | 9 | 各自 focus+材料+评分 schema | 扣分制 scorecard | 盲评隔离：不见阈值与他人输出 |

**串行降级**: 当前环境无子 agent 能力时, 按本文各挂接点的串行路径执行并告知用户耗时约 N 倍; 不伪造并行。

### 模型档位路由 (v2.0.0)

子 agent 不必全用同一模型。按角色的上下文敏感度与质量要求配档（宿主有路由表时对齐宿主的，如 AGENTS.md 的调度规则）:

| 档位 | 适用角色 | 理由 |
|---|---|---|
| 经济档 (快/便宜) | 题面提取员、一致性审计员（机械核对）、批量格式处理 | 结构化提取与核对，不深推理 |
| 精品档 (强推理) | 审题质询员、子问求解员、评委席位、章节起草员 | 建模判断与终审质量决定上限 |
| 跨家族第二意见 | 代码审计员、评委终审复评 | 与主 agent 不同模型家族，防同源盲区 |

原则：识图/读视频类任务先由多模态能力完成理解、产出结构化文字，再派给无视觉的执行角色——禁止让无视觉模型"顺便读图"。迭代预算见下文纪律，档位升级（经济档反复失败 → 精品档）算入预算消耗。

### 派发决策表

先过这张表, 不满足左列条件就直接走串行, 不为了并行而并行:

| 条件 | 不满足时的处理 |
|---|---|
| 任务间无数据依赖（读同一输入不算依赖, 写同一输出才算） | 有依赖的拆成两批, 批内并行批间串行 |
| 任务产出可结构化验收（JSON/文件/清单） | 验收标准写不清的任务不派 |
| 单任务预期 ≥30 min | <15 min 的任务合并或主 agent 自做 |
| 共享表已冻结 | 未冻结先冻结再派, 否则合并必冲突 |
| 用户已知情并行会复制上下文（token 成本） | 追问一次再派 |

## 挂接点 1: Stage 1 选题 — 三题并行分析

对候选题（通常 2-3 道）并行做"题面结构化提取", 每题一个子任务:

| 提取字段 | 说明 |
|---|---|
| 题型判定 | 主型 + 副型（优化/评价/预测/机理/统计） |
| 数据状态 | 附件数量、规模、脏数据风险 |
| 方法候选 | 3-5 个, 各带适用性理由 |
| 风险清单 | 数据缺陷、规模爆炸、知识盲区 |
| 团队匹配度 | 与 stage 0 记录的团队强项对照 |

- 每个 prompt 附: 题面 PDF/文本路径、提取字段表、输出 JSON 格式。
- 主 agent 汇总进决策矩阵（`stage_01_problem_selection.md` 的选题矩阵）, 不让子 agent 直接下结论。
- 串行降级: 逐题提取, 每题 20-30 min。

## 挂接点 2: Stage 5 子问循环 — 无依赖 Qi 并行求解

**前提判定**: 读 `decision_log.stages.2.subproblem_dependency`; 题面无依赖的 Qi（如 Q1 与 Q2 都只依赖原始数据, 互不引用）可并行, 有依赖的 Qi（Q3 用 Q2 输出）保持串行。

并行流程:

```
1. 冻结写锁: stage 4 符号表 + 假设表 + 术语表 冻结快照, 写入 decision_log
2. 逐 Qi 派求解包: 每个子 agent 一个 Qi, prompt 含:
   - 冻结版符号表/假设表全文（不是指针）
   - 该 Qi 的子问题卡片 + 选定模型 + toy demo 结果
   - 代码骨架路径 (templates/shared/code_starter/<type>.py)
   - 验收标准: stage_05 单 Qi 循环 A-G 全走完, 产出写入 results/Qi/
3. 主 agent 合并: 逐 Qi 收 key_metrics + decision_log 片段
4. 合并冲突检查（必做）:
   - 符号: 两个 Qi 是否定义了同名不同义符号
   - 单位: 同一物理量单位是否一致（元 vs 千元）
   - 编号: 图号/表号/公式编号是否冲突
   - 假设: 是否有子 agent 私自加了新假设（违反写锁）→ 回滚或走 L2 补假设
5. 冲突以 decision_log 已冻结字段为准, 子 agent 侧改
```

串行降级: 沿用 `stage_05_subproblem_loop.md` 原始单 Qi 循环。

**求解包 prompt 骨架**（每个 Qi 一份, 主 agent 填空后派发）:

```text
任务: 独立求解子问题 Q2, 走完 stage_05 单 Qi 循环 Step A-G。
输入（只读, 不得修改）:
  - 题面: <path/to/problem.pdf 的文本提取>
  - 冻结符号表/假设表: <全文粘贴, 不是路径指针>
  - 本问子问题卡片 + 选定模型 + toy demo 结果: <粘贴 stage.2/3 相关字段>
  - 代码骨架: <skill>/templates/shared/code_starter/<type>.py
验收标准:
  1. results/ 下有 Q2_model.tex + Q2_solve.py + 结果 csv/npy (扁平命名 results/Q2_*, 与 stage_05 canonical 命名一致, 后续脚本据此发现产物)
  2. sanity check 四项全过, 关键状态打印保留
  3. ≥1 张 Type 3 论文图 + 图表契约字段齐全
  4. 输出 decision_log 片段 JSON (model_name/key_metrics/physical_meaning_summary)
  5. 符号与冻结表一致; 若确需新符号, 在返回 JSON 的 pending_symbols 字段登记, 不自行引用
禁止: 修改 state/ 下任何文件; 修改其他 Qi 的产物; 引用未冻结的假设。
```

**合并冲突检查可脚本化部分**（主 agent 在合并时跑）:

```bash
# 符号同名冲突: 各 Qi 数学表述中出现但不在冻结符号表里的新符号
grep -ohE '\\\\[a-zA-Z]+(_\{?[A-Za-z0-9]+\}?)?' results/Q*_model.tex | sort | uniq -c | sort -rn
# 单位口径冲突: 同一物理量两种单位并存
grep -n "千元\|万元" results/Q*_model.tex   # 与 "元" 混用即人工裁决
# 图号冲突: 各 Qi 图文件重名
ls figures/ | sort | uniq -d
```

## 挂接点 3: Stage 8 写作 — 分节并行起草

可并行的节: §1 问题重述、§2 问题分析、§3 假设、§4 符号、各模型节 §5.i、§6 灵敏度、§7 评价、附录。

**不并行**: 摘要与结论由主 agent 最后写（摘要三遍制见 `stage_08_writing.md`; 摘要是全文浓缩, 需要全部正文视野, 派出去会被局部视角绑架）。

- 每节 prompt 自包含: 该节的 decision_log 输入路径、竞赛 phrase_bank/anti_patterns 路径、字数与结构要求、图号表号占位约定（如 §5.1 用 图 5-x 占位, 合并时统一编号）。
- 合并后主 agent 跑**一致性回检**（必做清单）:

| 检查项 | 方法 |
|---|---|
| 符号表一致 | 各节符号 vs stage 4 符号表逐个 grep |
| 数值引用一致 | 各节出现的定量结果 vs `evidence_ledger` / results/ 文件 |
| 图号表号连续 | 合并后全文编号重排, 无跳号重复 |
| 术语统一 | 同一概念多种叫法（"残差/误差项"混用）→ 以术语表为准 |
| 节间衔接 | 每节开头是否承接上一节, 无断崖 |

- 回检不过的节退回该节的子 agent 上下文修（若有）或主 agent 自修, 计入该节 refine 轮次。
- 串行降级: 按 `stage_08_writing.md` 写作顺序逐节写。

## 迭代预算纪律

| 预算 | 上限 | 耗尽后动作 |
|---|---|---|
| 每阶段 refine | ≤ 3 轮（沿用现有 L1 协议） | carryover 进 decision_log, 下阶段处理 |
| 并行任务失败重派 | ≤ 2 次/任务 | 换串行或换任务规格 |
| 全程并行任务总数 | 每挂接点 ≤ 题数/节数, 不超额拆分 | 拒绝过度拆分: 单任务 < 15 min 的不派 |

**预算耗尽 → 结构化 decision_memo, 不静默继续**。任何并行任务在重派 2 次后仍失败, 主 agent 输出:

```json
{
  "type": "decision_memo",
  "blocked_item": "Q2 求解包 (并行任务)",
  "tried": ["并行求解 v1 (符号冲突被合并回检打回)", "重派 v2 (solver 超时)"],
  "best_so_far": "toy demo 可跑, 全量数据 MILP 超 30 min",
  "options": [
    "降级为启发式求解 (SA/贪心), 牺牲最优性",
    "缩小规模: 只对前 20% 变量精确求解, 其余贪心",
    "接受串行慢跑, 从其他 Qi 借时间"
  ],
  "recommendation": "选项 1, 理由: 时间预算优先, 启发式可给出误差界"
}
```

memo 以编号菜单呈现用户（1)-3) + 兜底"让我决定"）, 用户拍板后写入 `decision_log.events.log`, 继续推进。

## 风险控制

1. **不共享中间稿**: 并行子任务互不可见, 合并前主 agent 是唯一持有全局视野的角色。
2. **合并冲突裁决**: 一律以 decision_log 已冻结字段（符号/假设/术语/编号基线）为准; 冻结字段本身要改时必须走 L2 backtrack, 不在合并环节顺手改。
3. **用户文件保护**: 子 agent 只能 patch/新文件/先备份后覆盖; 主 agent 合并时抽查是否留了备份。
4. **token 成本**: 并行 = 上下文复制, 每个子任务 prompt 控制在必要输入以内（冻结表全文 + 本任务规格）, 不夹带无关阶段历史。
5. **降级透明**: 任何时刻从并行降级到串行, 必须告知用户并更新时间预估。

## 与反馈层的接口

- 并行不改变反馈协议: 每个子任务产出仍走各自挂接点的 L1 自评（如 Stage 5 per-Qi rubric）, 由子 agent 自评、主 agent 收口。
- 合并冲突检查发现的问题按严重度分流: 符号/单位冲突 → 就地修; 假设表被违反 → L2 backtrack（回 stage 4 补假设并评估是否重跑下游 Qi）。
- decision_memo 写入 `decision_log.events.log`（type=decision_memo）, 与 backtrack/panel 事件并列, 供 Stage 9 终审回溯。
