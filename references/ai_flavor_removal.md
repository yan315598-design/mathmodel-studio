# 去 AI 味写作规范

> 0.7.4 新增：识别并消除数模论文中的 AI 写作痕迹。评委对模板腔/机器腔敏感, 一眼"AI 味"直接压档。本文给出痕迹识别、禁用词表、真实感注入与检查流程。

---

## 十类 AI 写作痕迹（坏例 → 好例）

### 1. 超高频连接词

"首先/其次/再次/最后"四连、"综上所述"、"值得注意的是"、"总的来说"高频出现。

- 坏例: 首先, 本文对数据进行清洗。其次, 建立模型。再次, 求解。最后, 分析结果。综上所述, 模型效果较好。
- 好例: 数据清洗剔除 12 个异常记录后, 建立熵权-TOPSIS 评价模型; 求解得到的排序结果与消除率实测趋势一致。

改法: 连接词换成内容衔接——用"在……之后""基于上一问的 x*""相比之下"等有信息量的过渡, 或直接删。

### 2. 空泛评价词（无数值）

"显著提升""具有重要意义""效果较好""明显优于"后面不跟数字。

- 坏例: 本文模型显著提升了预测精度, 具有重要的实际意义。
- 好例: 本文模型将测试集 RMSE 从 2.95 降至 2.31（降幅 21.7%）, 相对贪心基线的优势在 ±10% 参数扰动下保持。

### 3. 排比三段式与过度分点

每段都是 1) 2) 3), 每节结尾都凑三点, 层层"三大块"。

- 坏例: 本文的创新点有三: 一是……; 二是……; 三是……。（且后文每节都复刻这个句式）
- 好例: 本文的主要改进在约束处理: 把预算约束从硬约束改为机会约束后, 可行域扩大 8.3%, 目标值提升 5.1%。（要点有几个写几个, 不凑数）

### 4. 形容词堆砌与宣传腔

"强大的""高效的""创新的""完美的""极大地"连用。

- 坏例: 本文提出的强大算法高效地解决了这一创新性问题, 极大地优化了性能。
- 好例: 算法在 50 变量实例上 12.3 s 收敛; 规模扩到 500 变量时需 6.2 min, 见附录 A 的时间扩展实验。

### 5. 无主语句式泛滥

"通过……得到……""经过分析可知""需要指出的是"整段没有动作主体。

- 坏例: 通过上述分析, 可以发现所建模型具有较强的适用性。需要指出的是, 该方法同样适用于其他领域。
- 好例: 上述检验均针对 2023 年数据; 换用 2022 年数据复跑, 排序前五名不变, 第 6-8 名互换（表 6）。

### 6. 段落长度完美对称

每段都是 3-4 句、字数接近、结构雷同, 读起来像流水线产出。

- 改法: 刻意打破对称——推导段可以一段 6 句, 结果段 2 句加一张表, 讨论段长短交错。先有内容节奏, 再有排版。

### 7. 英文直译腔

"通过……的方式""对……进行……"连用、"基于……的……的"多层嵌套定语。

- 坏例: 通过采用线性加权的方式对指标进行归一化处理, 从而实现对对象的进行综合评价。
- 好例: 指标按 min-max 归一化后线性加权合成综合得分。

### 8. 总结句复读前文

每节结尾用一两句把本节内容原样复述一遍, 无新增信息。

- 坏例: 本节建立了 XX 模型并进行了求解, 为后续分析奠定了基础。（"奠定了基础"×N 节）
- 好例: 直接删, 或换成承下信息: 下一问将沿用本问的 x* 作为输入, 故其 5% 的求解误差会向下传导。

### 9. 可数化配额（频率配额表）

> 0.7.5 新增。前八类靠语感识别, 本类**可数**——频率配额表超配额即改, 不用争论"算不算 AI 味"。配额按全文计（摘要 + 正文, 附录不计）。

| 类别 | 词 | 配额（全文） | grep 自查命令 |
|---|---|---|---|
| 连接词类 | 此外 | ≤2 次 | `grep -o "此外" paper_workspace/*.md paper_workspace/sections/*.tex \| wc -l` |
| 连接词类 | 综上所述 | ≤1 次 | `grep -o "综上所述" paper_workspace/*.md paper_workspace/sections/*.tex \| wc -l` |
| 连接词类 | 值得注意的是 | ≤1 次 | `grep -o "值得注意的是" paper_workspace/*.md paper_workspace/sections/*.tex \| wc -l` |
| 评价词类 | 显著 | 仅允许出现在有统计检验 p 值或量化对比处 | `grep -n "显著" paper_workspace/*.md paper_workspace/sections/*.tex` 后逐条人工核验 |
| 英文场景 | em dash（—） | ≤2 处 | `grep -o "—" paper_workspace/sections/*.tex \| wc -l` |
| 英文场景 | moreover + furthermore 合计 | ≤2 次 | `grep -nio "moreover\|furthermore" paper_workspace/sections/*.tex \| wc -l` |
| 英文场景 | notably / crucially / remarkably | 0 次 | `grep -nio "notably\|crucially\|remarkably" paper_workspace/sections/*.tex`（空输出才通过） |

判读规则:

1. 连接词类超配额 → 删到配额内, 换内容衔接（同第 1 类改法）。
2. "显著"逐条核验: 所在句必须有 p 值（如 p<0.05）或量化对比（如"较基线提升 12.3%"）, 二者皆无就改写——"显著"是统计学术语, 不是形容词 filler。
3. 英文配额适用于 MCM/ICM 英文稿; 中文稿的 em dash 同样按 ≤2 控制。
4. 配额是上限不是目标: 写完一遍零命中不需要往回补。

### 10. 工作流话术泄漏（工程痕迹进正文）

> 0.7.5 新增。skill 内部流程术语、脚本与目录痕迹出现在论文正文, 评委读到的不是"建模过程"而是"某个工作流的运行日志"——比模板腔更致命, 因为它暴露的是机器流水线本身。

**规则**: 论文正文（摘要 / 引言 / 模型 / 结果 / 结论）不得出现以下任何一类痕迹; 附录代码清单（MCM 等 reveal 要求附代码的）不受本条限制, 但附录里也不写流程术语, 只放代码与说明。

- 工作流内部术语: "stage""decision_log""真源""证据账本""冻结""skill""agent""workflow""harness""dispatcher""rubric""anchor""red-team" 等。
- 工程文件痕迹: 脚本文件名（`.py` 结尾）、数据文件名（`.json`/`.sha256` 结尾）、目录名（`results/`、`paper_workspace/`、`state/`）。
- AI 协作痕迹: "prompt""LLM""GPT""待核验""占位符" `{{ }}` 残留。

10 条正则自查清单（命中后**人工过滤语境**再删改——个别词在特定领域是合法术语, 见判读 3）:

```bash
# 1. stage 流程术语
grep -nE "[Ss]tage[ _-]?[0-9IV]+|阶段 ?[0-9]+ ?输出" paper_workspace/*.md paper_workspace/sections/*.tex
# 2. 决策日志 / 状态机
grep -nE "decision[_ ]log|状态机|评分历史" paper_workspace/*.md paper_workspace/sections/*.tex
# 3. 中文内部术语
grep -nE "真源|证据账本|口径冻结" paper_workspace/*.md paper_workspace/sections/*.tex
# 4. 冻结话术
grep -nE "冻结|freeze|frozen" paper_workspace/*.md paper_workspace/sections/*.tex
# 5. skill / 工作流词汇
grep -nE "skill|workflow|harness|dispatcher|rubric|anchor" paper_workspace/sections/*.tex
# 6. agent（ABM 语境除外, 见判读 3）
grep -nioE "agent|智能体调用" paper_workspace/*.md paper_workspace/sections/*.tex
# 7. 脚本与数据文件名
grep -nE "[A-Za-z0-9_/-]+\.(py|json|sha256)" paper_workspace/*.md paper_workspace/sections/*.tex
# 8. 工作区目录名
grep -nE "results/|paper_workspace/|state/|_archive/" paper_workspace/*.md paper_workspace/sections/*.tex
# 9. AI 协作痕迹与占位符残留
grep -nE "prompt|LLM|GPT|待核验|占位符|\{\{" paper_workspace/*.md paper_workspace/sections/*.tex
# 10. 流程审查话术
grep -nE "red.?team|复盘|兵检|流水线" paper_workspace/*.md paper_workspace/sections/*.tex
```

判读规则:

1. 命中 ≠ 违规: 逐条人工过滤语境, 确属工作流话术的删或改写成学术表达（"经决策日志登记" → "本文在方法比较后选定 X"）。
2. 目录与文件名需要指代时, 用论文自己的编号体系（"附件 1 数据""式 (12) 的求解结果"）, 不用工作区路径。
3. 已知合法例外: "agent / 智能体" 在多智能体建模（ABM）语境、"冻结" 在冷冻/低温物理或价格冻结等题目语境属正常术语, 保留; 但同词若同时出现工作流语义（"结果数字已冻结"）仍须删改。
4. 本类与第 9 类同为 Stage 9 终审必查项, 与文末 grep 自查命令并列执行。

## 数模禁用/慎用词表

| 禁用/慎用词 | 改写法 |
|---|---|
| 赋能 | 写清楚具体作用: "该约束将利用率从 87% 提到 95%" |
| 抓手 | 删; 或写"切入点/着力点"并落到具体变量 |
| 闭环 | 数学上写"迭代至收敛判据 \|Δf\|<ε"; 管理语境的"闭环"整句重写 |
| 颗粒度 | "分辨率/离散间隔/时间步长", 写出具体值 |
| 显著提升（无数字） | 提升多少: 数值 + 对比基线 + 区间 |
| 具有重要意义 | 写对谁、在什么指标上有多少改进 |
| 强大的 / 高效的 | 给运行时间、规模、收敛代数 |
| 完美地 | 删。完美不可证; 写"在测试范围内未发现反例" |
| 综上所述 | 删或换"综合三问结果" |
| 值得注意的是 | 删, 直接说事实 |
| 总的来说 | 删 |
| 一定程度上 | 写明程度: 区间/百分比/条件 |
| 大幅 / 极大 | 换成数值 |
| 全新的 / 首创的（无出处） | 写改进点与最近邻工作的差异, 不称首创 |

## 真实感注入清单

人工痕迹的本质是**具体性和不对称性**。逐项检查:

1. 写具体数值与单位: 每个结论句能落到数字（最优值/误差/百分比/秒）。
2. 写失败尝试与为什么放弃: "先尝试 Gurobi 精确求解, 500 变量实例 30 min 未收敛, 改用 SA"。
3. 写参数权衡过程: "种群规模取 50 而非 200: 后者耗时 4 倍但目标值仅改善 0.3%（图 7）"。
4. 写数据缺陷与处理: 缺失比例、异常剔除条数、为何选 3σ 而不是 IQR。
5. 句式长短交错: 连续三句等长即改一句。
6. 敢报负面结果: 某方法在本题数据上不 work 也写出来（呼应华数杯 6 维里的诚实度维）。

## 反模板化规则

1. phrase_bank 同款句式**每节最多用 1 次**: 从句式库挑骨架后必须换词改写, 不整句照抄。
2. **诚实命名**: 模型名保持"限定词 + 核心模型"且与实际所作一致——用了熵权法就不能叫"改进 TOPSIS 综合评价体系"来凑高级感; 限定词只写真正做出的改进（呼应真源纪律: 名字与内容 1:1）。
3. 各节开头不复用同一句式模板（如每节都以"为了解决 XX 问题, 本文……"开头）。
4. 图表解释句同款句式（"由图 X 可见……说明……"）全文不超过总图数的一半, 其余换成比较句/因果句/质疑句。

## 摘要专项（AI 味最致命的位置）

评委 3 分钟扫摘要, 模板腔在这一段杀伤力最大。摘要写完后单独加检:

| 坏例（AI 味） | 好例（改后） |
|---|---|
| 针对问题一, 本文建立了优化模型, 取得了良好的效果。 | 针对问题一, 建立"机会约束-拉格朗日松弛"模型, 最优利润 87234 元, 较贪心基线提升 12.3%。 |
| 本文综合考虑多种因素, 具有较强的实用价值。 | 综合预算、产能与需求三类约束, 预算利用率达 99.4%。 |
| 首先……其次……最后, 本文圆满完成所有任务。 | （删连接词）三问共用同一符号体系与数据管道, Q3 直接复用 Q2 的 x* 作输入。 |

摘要红线: 无数值结论、模型无名、五段结构完美对称且句式雷同、结尾"具有重要意义"式升华。

## 常见误判（这些不是 AI 味, 不要改）

1. 标准数学术语与公式推导（"不妨设""注意到""证毕"）——学术惯例, 保留。
2. 必要的编号列举（约束条件 C1/C2、假设 1-5）——结构化表达是数模论文的要求。
3. 图表引用句（"见图 X"）——引用本身无罪, 罪在同款句式连发。
4. phrase_bank 句式的合规使用——每节 ≤1 次的改写使用是设计内行为（见反模板化规则 1）。

判断口径: 一处痕迹是巧合, 一页痕迹是风格, 全文痕迹是机器。按"每节 8 条自查"控制密度即可, 不必逐词猎巫。

## 整段改写示例（多类痕迹叠加的典型段）

改写前（叠加痕迹 1/2/4/7/8）:

> 首先, 本文对附件数据进行了预处理。其次, 通过采用 3σ 准则的方式对异常值进行识别与剔除, 显著提升了数据质量。最后, 对清洗后的数据进行归一化处理。综上所述, 本节的数据预处理为后续建模奠定了坚实的基础。

改写后:

> 附件 1 的 3128 条记录中, 流速字段有 47 条缺失（1.5%）, 按时间段线性插值补齐。对剩余记录用 3σ 准则识别出 9 条异常（超出均值±3σ, 占 0.3%）, 逐条核对后判定为传感器故障并剔除; 改用 IQR 准则复检, 无新增异常。清洗后流速分布偏度由 1.8 降至 0.6, 满足后续正态性假设的检验前提（Shapiro-Wilk p=0.21）。

对照要点: 连接词清零、每句话带数字、写了复检（失败尝试的变体）、无总结句复读、句长交错。

## 检查流程

### Stage 8: 每节成稿后 8 条自查（yes/no）

| # | 检查项 | 目标 |
|---|---|---|
| 1 | 本节无"首先/其次/再次/最后"四连与"综上所述/值得注意的是/总的来说" | 全 no |
| 2 | 本节每个评价性结论都带数值或明确指向 | 全 yes |
| 3 | 本节分点不为凑三段 | yes |
| 4 | 本节无宣传腔形容词连用 | 全 no |
| 5 | 本节无"通过……的方式/对……进行……"直译腔连用 | 全 no |
| 6 | 本节段落长度不等长 | yes |
| 7 | 本节结尾无复读式总结 | no |
| 8 | 本节 phrase_bank 同款句式 ≤1 次 | yes |

任一条不过 → 本节就地修改后再进下一节, 不攒到终审。

### Stage 9: 终审必查项

1. 全文 grep 禁用词表（命令见下）, 命中逐条处理。
2. 摘要单独过一遍 8 条自查（摘要 AI 味最致命）。
3. 抽查每个模型节是否有至少一处"失败尝试/参数权衡/数据缺陷"描述（真实感注入 2-4）。

### grep 自查命令示例

```bash
# 高频连接词与空泛评价
grep -n "综上所述\|值得注意的是\|显著提升\|总的来说\|具有重要意义" paper_workspace/*.md paper_workspace/sections/*.tex
# 互联网黑话与宣传腔
grep -n "赋能\|抓手\|闭环\|颗粒度\|强大的\|完美地" paper_workspace/*.md paper_workspace/sections/*.tex
# 直译腔
grep -n "通过.*的方式\|对.*进行" paper_workspace/sections/*.tex
```

命中即回改; "对……进行"允许少量存在（中文正常用法）, 连用 ≥3 处/节才算痕迹。
