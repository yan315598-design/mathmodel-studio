# 中文竞赛论文呈现规范 (cn_presentation_spec)

> v2.7.0 新增：中文竞赛论文的**呈现层**验收规范（cumcm / huaweibei / huashubei / diangong / apmcm 通用），stage 8 写作与 stage 9 终审的呈现层唯一权威源。mcm 英文赛只参考 §5-§8 的通用条款。
> 依据：2026 国赛 A 题全程实测（用户 09-11 格式反馈 10 条、压力测试台账 T-01~T-09；实测记录存于用户工作区 `state/`，不入库）与 2025 优秀论文 A196（64 页）的视觉对比。
> 分工：`md_authoring_spec.md` 管 md 真源的**写法**（公式/符号/题注语法、双链行为），本文件管编译成品的**呈现**（版面/标点/摘要/图表纪律/写作 voice）。页数口径以本文件 §1.6 为准。

读法：每条规则三段——**为什么**（一句话，引实测事故或 A196 对照）→ **怎么做** → **自查**（可直接运行的命令或检查法）。自查命令在论文工作区（`paper_workspace/`，含 01..10_*.md）或编译输出目录下运行。

## 1. 版面硬规范

### 1.1 页面与边距
- 为什么：版心是评委对"正规程度"的第一眼判断；2026 A 题实测中自建编译链导致模板边距漂移（T-01 连锁）。
- 怎么做：A4 纸、四边距 ≥2.5cm（以当年通知复核）；LaTeX 用 `geometry{a4paper, top=2.5cm, bottom=2.5cm, left=2.5cm, right=2.5cm}`（6 套模板已带），改动需登记 decision_log。
- 自查：`grep -n "geometry{" templates/latex/<comp>/main.tex`；编译后 PDF 标尺目测四边。

### 1.2 页码
- 为什么：页码位置与起算混乱直接打断评审翻页定位（用户 09-11 反馈命中项）。
- 怎么做：页码放**页脚居中**，自摘要页起算（摘要页 = 第 1 页）；`\pagestyle{plain}` 即页脚居中（ctexart 默认），摘要前不加 `\pagenumbering{roman}` 之类的前置页码。
- 自查：翻 PDF 前 3 页看页脚数字；`grep -n "pagestyle\|pagenumbering" main.tex` 确认无页眉页码。

### 1.3 页眉
- 为什么：页眉出现章节名/队信息既是视觉噪声也是匿名性风险；自建链最常漂移的就是页眉。
- 怎么做：**禁用页眉**（除非当年通知明确要求）；页眉不得出现章节名、队号、校名。
- 自查：`grep -n "fancyhead\|markboth\|fancyhdr" main.tex` 应为空（或仅当年通知要求的场合，并登记）。

### 1.4 摘要独占页
- 怎么做：摘要独占第 1 页（不与正文同页），正文自第 2 页起；tex 中摘要块后 `\newpage`。
- 自查：PDF 第 1 页末尾不应出现"一、问题重述"等正文标题。

### 1.5 禁止压缩版面凑页数
- 为什么：2026 A 题实测中 agent 因页数口径不一致恐慌性压缩（行距 1.3→1.15、图 19→10 张，T-04/S-06），版面窒息、信息密度反而下降；A196 对照显示优秀论文版面有呼吸感。
- 怎么做：下限 = 行距 **≥1.25**、正文不小于**小四**；页数超区间时只删内容或调图表数量，**不得**压行距/字号/图幅/页边距。**图表题字号随当前链模板**——tex 链由 `templates/latex/<comp>/main.tex` 的 `\captionsetup` 定义，docx 链由 `templates/docx/reference.docx` 的题注样式定义（宋体小五 9pt 居中），本规范不另立第二套题注数值。
- 自查：`grep -n "linespread\|zihao\|fontsize\|captionsetup" main.tex` 核对设置；PDF 目测相邻两行不粘连、图表题不小于正文脚注级。

### 1.6 页数口径（全文统一表述）
- 为什么：页数口径三处不一致（T-04/S-06）是恐慌性压缩的直接根因。
- 怎么做：统一表述——中文竞赛**无硬上限时按当年通知，不作硬阻断仅提示**；骨架建议 22-25 页指**正文+参考文献，附录不计**。stage 9 汇报页数时必须带口径说明。与 `submission_checklists.md` cumcm 节同源，两处表述需同步。

## 2. 标点与字符规范（全角体系）

### 2.1 原则
一句话：**中文语流用全角，拉丁/数学语流用半角，两套不在同一语流内混排。**
- 为什么：用户 09-11 反馈多条命中；半角标点混入中文是"AI 生成感"与排版粗糙的最强信号之一，A196 全文全角体系。

### 2.2 中文语句全角清单
，。；：？！（）“”——……《》、～

### 2.3 禁用 → 替代
| 禁用 | 替代 | 说明 |
|---|---|---|
| ASCII 直引号 `"..."` / `'...'` | “ ” / ‘ ’ | 中文引语一律弯引号 |
| 半角括号包中文 `(中文)` | （中文） | 括号内是中文语流即全角 |
| `--` 或单个 `-` 表破折 | —— | 连接复合词（多产品—多时段）也用全角一字线 |
| `...` | …… | 省略号 |
| 半角 `, ; : ? !` 紧贴中文 | ，；：？！ | 中文语句内一律全角 |
| 裸半角连字符范围 `1-10` | 1～10 或 "1 至 10" | 数字范围二选一，全篇统一（§2.5） |

### 2.4 允许半角的场景（白名单）
1. 公式内（`$...$` / `$$...$$` 内的一切，含 `(12, 0, 25, ...)`）；
2. 代码块与伪代码；
3. 英文缩写与专有名词（MILP、CVaR-95%、LHS、warm start）；
4. 数值与单位（47 s、12.3%、±10%、1.5 MW）；
5. 参考文献条目内部（GB/T 7714 的英文标点、页码卷期 `2024, 20(3): 1-10`）；
6. 表格纯数值/纯英文单元格。

### 2.5 数字范围符号
- 怎么做：全篇统一用"至"或"～"其中一种，登记 decision_log；禁止 `1-10` 裸连字符（与负号/破折混淆）。

### 2.6 grep 自查表（标点 6 项，md 源上运行）

1. ASCII 直引号贴中文：

   `grep -nP '[\x{4e00}-\x{9fff}]"|"[\x{4e00}-\x{9fff}]' *.md`

2. 半角括号包中文（左括号贴中文或中文后跟左括号）：

   `grep -nP '\([\x{4e00}-\x{9fff}]|[\x{4e00}-\x{9fff}]\(' *.md`

3. `--` 破折（表分隔行 `---` 与长横线不误报）：

   `grep -nP -- '(?<!-)--(?!-)' *.md`

4. `...` 省略：

   `grep -nP '\.\.\.' *.md`

5. 半角逗号/分号/冒号贴中文：

   `grep -nP '[\x{4e00}-\x{9fff}][,;:]|[,;:][\x{4e00}-\x{9fff}]' *.md`

6. 半角问叹贴中文：

   `grep -nP '[\x{4e00}-\x{9fff}][?!]' *.md`

命中处理：逐条判是否落在 §2.4 白名单（公式/代码/文献条目内），白名单内豁免，其余改全角。

### 2.7 中英混排空格（迁自旧层 distilled_formats.md §5, 原文保留；原件已随 v3.3.0 移出公开仓库）

- **中英混排**: 中文与英文术语之间保留半角空格, 例如 `LSTM 模型`、`AHP-熵权模型`、`Python 调用`。
- **三个例子**:
  1. `本文采用 LHS 对参数进行扰动, 并在 ±10% 区间内观察输出变化。`
  2. `针对 WLAN 网络信道接入问题, 本文建立统一吞吐模型。`
  3. `通过 Python + cvxpy 求解后, 得到最优解。`
- **注意**: 数字、单位、英文缩写不要与汉字挤在一起, 否则版面会显得很“Word 默认模板”。

## 3. 摘要呈现

结构、句式与填空见 `competitions/cumcm/abstract_template.md`（含完整示例），本节是验收口径。

### 3.1 结构
- 怎么做：段 1 背景（100-150 字）→ **“针对问题N：”导语段 ×N**（每问一段）→ 灵敏度段 → 创新推广段 → 关键词。
- 为什么：这是 A196 摘要可扫读的核心特征；2026 A 题摘要曾被反馈"读不出每问答案"。

### 3.2 每问段三句式
- 怎么做：段首“针对问题N：”（全角冒号、N 用中文数字与题面一致），段内 **方法一句 → 求解一句 → 结果一句**；每问 2-4 个定量数字，只放最终结果与关键对比，中间量不进摘要。
- 自查：`grep -n "^针对问题" 01_abstract.md` 逐段核对三句式与数字个数。

### 3.3 关键结果加粗（6-12 处）
- 怎么做：每问**最终答案** + **关键方法名**加粗，全摘要合计 6-12 处；加粗是路标不是荧光笔，超过 12 处等于没加粗，少于 6 处扫读断链。
- 自查（盲测）：只读摘要加粗处，能否复述每问答案——能则过。计数：`grep -o '\*\*[^*]*\*\*' 01_abstract.md | wc -l`。

### 3.4 关键词
- 怎么做：4-6 个；“**关键词：**”含冒号整体加粗；条目分隔符全文统一（推荐中文分号"；"），不混用逗号/顿号。
- 自查：`grep -n "关键词" 01_abstract.md` 看分隔符与加粗。

## 4. 标题体系

### 4.1 两种合法风格（选定其一）
- (a) 全阿拉伯左对齐黑体：1 / 1.1 / 1.1.1（LaTeX `\section` 默认形态）；
- (b) 章中文序号居中（一、二、三……）+ 节阿拉伯数字。
- 为什么：两种风格混用是排版事故高发区；A196 用 (a)。选定后**全文一致**并登记 decision_log（stage 0 决策项）。
- 自查：PDF 目录/正文标题逐级目测，无"一、"与"1"并存。

### 4.2 编号单一来源
- 怎么做：编号只来自 LaTeX 自动编号（`\section`/`\caption`/公式环境）；md 真源不手写章节号（标题行写纯文字，渲染链自动编号）。
- 为什么：手写编号在增删章节后整体漂移（T-02 同类事故）。
- 自查：`grep -nE "^#{1,3} +[0-9一二三四五六七八九十]+[、.]" *.md` 应为空。

## 5. 公式

### 5.1 排版形态
- 怎么做：独立公式**居中 + 编号右顶格 + 全文唯一编号体系**，**默认全局连续 (1)(2)…**（2025 优秀论文 7 篇中 6 篇如此；章节级 (5.1) 需在 LaTeX 模板加 `\numberwithin{equation}{section}` 并登记 decision_log，md 手写编号侧仍写连续序号）；md 源写 `$$公式 \qquad (N)$$`，render_paper 升级 equation/align 后由 LaTeX 自动编号（见 `md_authoring_spec.md` §1）。
- **docx 链编号右顶格（v3.1.0 补，2026 A 题实测；窄支持，复杂形态回源）**：仅对**两种明确形态**做提号包表：(a) 独立 `oMathPara` 公式段 + 尾编号（`(N)` 前有 `\qquad` 渲染产物 = 幸存空白，H1 判据）；(b) **独立 `oMath` + 尾部纯编号段**（保守白名单：恰一个直接 `oMath`、编号在后、编号 run 纯为 "(N)"）——形似复杂形态（超链/字段/换行/嵌套/编号在前/夹带说明）**保持输入并告警**，须回源整形；`f(1)`/`a+(2)` 这类紧贴主体的括号**一字不动**（防静默改写数学内容）。两个**明确不假装支持**的边界：① **节末公式段**（段落自带 `sectPr`）跳过包表并告警 → 回源把公式移出节界；② **多栏节**（`w:cols num>1` 或列宽不等）宽度仍按单栏版心算并发**未支持警告**（每栏宽未建模）→ 多栏稿需回源评估或另处理。pandoc→docx 不产编号环境，`\qquad (N)` 的编号会留在公式对象内部、不右顶格。处置：导出时由呈现层后处理把每个带编号的 display 公式改写为**无边框三列表格**（窄空列｜公式居中｜编号右对齐普通文本），把编号从公式对象里提出来——`scripts/docx_presentation_postprocess.py` Step B（随 `export_final_docx.py --presentation` 默认执行、幂等；重导出自动重跑，无需手工介入）。md 源写法两链统一不变。
- 自查：编译后 PDF 抽查编号是否右顶格、居中；编号体系是否全文一种。docx 链自查：收集 PDF 文本层所有 `(N)` 形态 span 的右边缘 x1，中位数 ≈ 右边界（A4+2.5cm ≈ 524pt）且彼此相差 ≤3pt。

### 5.2 超宽必拆
- 怎么做：单条公式排版宽度超**版心 80%** 必须拆——`align` 多行（每行一个完整关系式）或拆子公式分条。
- 为什么：超宽公式顶破右边界，是 Overfull \hbox 的主要来源之一。
- 自查：§5.4 扫描 + PDF 目测右边距。

### 5.3 公式后衔接句
- 怎么做：每条独立公式后必接一句"它在模型里干什么"（约束含义/变量关系/求解入口），公式不裸奔。
- 为什么：公式堆叠无叙事 = 审计报告体，评委读不出模型主线。

### 5.4 Overfull 扫描（编译后必做）
- 命令（>5pt 逐条拆修）：
  `grep -E "Overfull \\\\hbox \(([5-9]|[0-9]{2,})\.[0-9]+pt" main.log`
- 全量计数：`grep -c "Overfull \\\\hbox" main.log`
- 验收：>5pt 项清零；修法优先级：拆公式 > 调断行 > 缩字号（最后手段）。

### 5.5 参数清单式公式
- 怎么做：同构参数定义式每行 ≤3 式可共用一个编号（`align` 内多行一码）。

### 5.6 公式字体正斜政策（v3.1.0 新增）
- 怎么做：全文公式字体**二选一并全文一致**——(a) 全局正体（变量一律不用斜体）；(b) 常规 GB 3102 惯例（**物理量斜体、单位/函数/说明文字正体——不是"全斜"**）。选择必须显式登记 `decision_log`，不得混用；**默认值由用户拍板**（2026 国赛 A 题工作区拍板为全局正体）。**政策未拍板时保持输入原状并向用户提示拍板，不得静默切换**（图内轴标签同此口径：随全文政策，见 `references/figure_skill_bridge.md` 图叙事章 ④）。docx 链的实现按**政策执行、不再无条件全刷**：`docx_presentation_postprocess.py --math-font auto|upright|conventional`（默认 `auto` = 读 `decision_log`）——`upright`（政策 a）注入/改写全部 `m:sty="p"`；`conventional`（政策 b）与**未登记/冲突**时**保持输入一字不动并警告**——注意 conventional 的语义是"**保留正确的混合输入**"（Word 默认即字母斜体/算符数字正体），**不是语义纠正、也不逐字符改写**（绝不把所有公式刷成斜体或正体之一）。**裸函数名（如 `exp`）源侧必须写成 `\exp`**：pandoc/OMML 只对 LaTeX 函数形式标正体，裸写会按普通字母变量渲染——这类问题**回源改 md**，不在 docx 上补。政策来源：`decision_log` 顶层 `math_font` / `math_font_policy` / `upright_math`（三别名查任一），`stages.0.notes` 作保守兜底；多路径冲突或取值非法 → 判 `unspecified` 并警告，交人工统一（解析器 `scripts/math_font_policy.py`）。Step A **不撤销**已存在的 `m:sty="p"`（pandoc 自身也给函数名/算符写正体，逐 run 无法区分）：若成稿已是"全刷正体"而政策改判 `conventional`，正确动作是**回源重导出**，不是在 docx 上反向刷斜。tex 链在模板统一设置；图内 matplotlib 侧同理——调用方按用户政策给 `figkit.apply_style` 传参（`upright_math=True` 全局正体 / `False` 显式复位常规斜体 / `None` 保持当前状态；**该函数不读 `decision_log`**），或直接控制 `mathtext.default`（`regular` / `it`）。
- 为什么：斜体与否本身不扣分，"同一篇里 t 时斜时正"必扣；政策不定则两条链、多个执行器各按各写，成稿必然混用。
- 自查：PDF 文本层检索数学斜体区段字符（U+1D400–U+1D7FF）——正体口径命中数必须为 0（政策 (b) 下改用"变量斜体、单位/函数正体"逐项核对；未拍板时不做此项判定，先记录为"未测"）。

## 6. 表格

### 6.1 三线表
- 怎么做：一律 booktabs 三线（`\toprule`/`\midrule`/`\bottomrule`），**无竖线、无底色**。
- 为什么：竖线网格表在中文竞赛评审习惯里是"外行"信号；A196 全部三线表。
- **docx 链实现（v3.1.0 补，2026 A 题实测）**：pandoc 给数据表挂 reference.docx 的 `Table` 样式且**不写直接边框**，成稿呈现由样式表决定、不保证三线。处置：由 `scripts/docx_presentation_postprocess.py` Step C/D/E（随 `export_final_docx.py --presentation` 默认执行、幂等，重导出自动重跑）对所有**不含 display 公式（oMathPara）的表格**写直接边框：上下 single 1.5pt（sz=12）、表头行单元格下边框 single 0.75pt（sz=6）、insideH/insideV/left/right 一律 none、底纹清 auto；公式编号包裹表（见 §5.1）保持无边框、天然跳过。
- 自查（docx 链，确定性）：编译后用 PyMuPDF `get_drawings()` 统计表格页矢量线段——**竖直线段数必须为 0**，水平线段数应等于「3 条制式线 × 列数 × 表数」（Word 按列分段画线）；tex 链沿用 PDF 目测 + `grep -c "vline\|tabularx.*\\|"` 源侧检查。

### 6.2 单元格居中
- 怎么做：单元格内容**居中**——**短列（数值/编号/单位）居中，长文本列整体左对齐**（列级统一，不逐格混排），并在表注说明。**表体整体居中、宽度自适应版心**（docx 链：`jc=center` + `tblW=100% pct` + `tblLayout=autofit`，列宽随内容重分配，**多节文档按逐节版心动态计算表宽**；长 token 列（路径/文件名）在 md 源给 `/`、`_` 后插零宽空格断行点，避免 Word 硬折）。**单元格文字零首行缩进、零段前段后、单倍行距**（docx 链：单元格段落直写 `spacing before/after=0, line=240 auto` + `ind` 全零，覆盖 Compact/Normal 样式继承）；**行禁拆**（docx 链：`trPr/cantSplit`，防单元格内容被页界劈半产生孤立残行）。
- 为什么：用户 09-18 反馈命中项；单元格缩进/段距/多倍行距继承自正文样式会让表格松散虚高，行跨页拆分产生残行。
- **节末公式段例外（v3.1.0）**：段落自身带节属性（`pPr/sectPr`）且内容是 display 公式时，后处理**跳过不包表并告警**（把带节属性的段落搬进表格会改动分节语义）——此类版面必须**回源调整 md、把公式移出节界**，不得在 docx 上就地处理；跳过的段数在导出日志 `[Step B]` 报告里核对。
- 自查：PDF 侧表格行基线距 ≈ 单倍（小四 ≈ 15.6pt）；表格页竖直线段 0、左右留白对称（docx 链用 PyMuPDF `get_drawings()`，见 §6.1 自查）；无跨页残行（每行首格与末格同页）；导出日志 `[Step D]` 的逐节表宽列表应覆盖多节文档的每一节。

### 6.3 所有表必须编号且被引用
- 怎么做：每个表有“表 N”编号且被正文引用；**不允许无编号的说明性小表**——要么给编号题注，要么把内容并入正文文字。
- 为什么：无题注 longtable 也会推进 table 计数器，造成后续表号整体偏移（T-02 实测）。
- 自查：`python <skill>/scripts/consistency_audit.py --workspace <项目根>`（即含 paper_workspace/ 的目录）图表引用闭环清零。

### 6.4 表题与表注
- 怎么做：表题在表格**上方**，≤1 行优先，格式统一（“表 N：说明”）；表注以“注：”起头、小五号，放表格**下方**——不得夹在题注行与表格之间（pandoc caption 识别陷阱，见 `md_authoring_spec.md` 避免清单）。
- 自查：md 源 `grep -n -B1 "^|" *.md` 确认题注行紧贴表格。

## 7. 图与图题

> 图型设计/判据线/对照构图/量化标签/示意图草稿通道的唯一权威源 = `figure_skill_bridge.md` 图叙事章（v3.0.0 起），本节不重述；本节仍只管图题与图内呈现纪律（R2 归属不动）。配色语义（判据线/基线/主模型/对照的颜色与线型绑定）唯一权威源 = `color_typology.md` 配色语义表。

### 7.1 图题
- 怎么做：图题在图**下方**，格式统一为 **"图 N 说明"**（图号与题名之间空一格、**不加冒号**；与 `md_authoring_spec.md` §3 的 md 写法一致，2025 优秀论文 7 篇中 4 篇同式）；**≤2 行**；逐面板的说明写进正文，不堆进图题。
- 为什么：长图题把图的视觉重心拉离图本身；A196 等优秀论文图题普遍一行。
- 自查：`grep -n "^!\[" *.md` 逐条数图题长度。

### 7.2 图内纪律（注释预算）
- 怎么做：图内**不放图名、不放结论句**；允许：轴标签/刻度/图例/面板标号/判据线/**每面板 ≤2 条解释性注释**。预算只数解释性注释——**判据线/参考线/图例/量化标签（柱顶数值、样本计数、R² 等短定量标注）均不计入注释预算**（判据线纪律见 `figure_skill_bridge.md` 图叙事章；量化标签纪律同章 ⑥）。
- 为什么：2026 A 题返工中图内注释膨胀回退（T-05/S-08），结论句进图既遮挡数据又与正文重复。
- 自查：出图后逐张目检标注条数；超预算的标注移表或正文。

### 7.3 图宽与图高
- 怎么做：多面板主图 **85-100% 版心**；单面板 **60-80% 版心**；物理高度 **≥5cm**（防"指甲盖图"）。LaTeX 侧 `width=0.85-1.0\textwidth` / `width=0.6-0.8\textwidth`；matplotlib 按 A4 版心 16cm 折算 figsize。
- 为什么：小图浪费版面且读不出细节，满幅单图又喧宾夺主；A196 多面板主图占满版心。
- 自查：`grep -n "includegraphics\|width=" main.tex`；PDF 目测高度。

### 7.4 面板标号
- 怎么做：多面板图标号 (a)(b)(c) 位置统一（全左上或全右上），与图题/正文引用的标号一致。

### 7.5 每图回答一个明确问题
- 怎么做：图题写"动作/结果 + 对象 + 条件"（如"误差随时间步长的收敛曲线"）；"XX 结果图"这类无主张图题不合格——先问这张图支撑哪条结论，答不出就不放。

### 7.6 图与图注同页、页尾留白（v3.1.0，清单 E6）
- 怎么做：docx 链没有 LaTeX 的浮动机制，图被推到下一页时会把图注留在上一页、并在上一页留下半页空白（2026 A 题终稿实测 p16/p28）。两步处置——① **不脱图**：导出后处理 Step F 自动给含图段落加 `w:keepNext`（`docx_presentation_postprocess.py`，随 `--presentation` 默认执行），图与紧随其后的图注强制同页；② **压留白**：半页空白是排版固有现象，只能靠"收束图前段落（把图前最后一段缩短 1–2 行）+ 按 §7.3 在下限内微调图宽/图高"往回收；仍留白 ≥1/3 页时，把该图与图注整体前移一节（改 md 图序），不要靠硬塞文字凑页。
- 为什么：图注脱离图是评委最容易误读的呈现缺陷；页尾大片留白被读作内容不足。
- 自查：docx 版 PDF 逐页看"图是否与图注同页 / 页尾空白是否 ≥1/3 页"；导出打印的 `[Step F] 图与图注同页: N 处` 应等于正文图片段数。

## 8. 正文写作 voice（重点前置体）

### 8.1 段落纪律
- 怎么做：每段 **≤6 行**（以版心行计）；段首 1-2 句给**结论/论点**，再展开依据。
- 为什么：评委扫读路径是段首；2026 A 题初稿是审计报告体（每段先铺过程再给结论），扫读困难。
- 自查：`awk 'BEGIN{RS=""} {n=split($0,L,"\n"); if(n>6) print FILENAME" 段"NR": "n" 行"}' *.md`（md 源行数近似，PDF 侧目测复核）。

### 8.2 结果段三步
- 怎么做：结果数 → 对比（基线/理论值/上一问）→ 意义（对决策或下一问的作用），三步一段完成。

### 8.3 加粗路标
- 怎么做：正文每节加粗 **≤3 处**，加粗对象与摘要的关键结论同一套（数字或判断句），不加粗过程性描述。

### 8.4 假设条数与长度
- 怎么做：假设 **≤8 条**、每条 **≤2 行**；超出的论证移正文"假设依据"小节，假设清单只留结论。
- 为什么：20 条假设各带论证段是 voice 失控的实测形态，评委无法确认哪些假设真正影响结论。

### 8.5 局限一句话式
- 怎么做：每条局限按"**假设 → 偏移方向 → 量级 → 代价**"一句话：例——"忽略二阶项会使边界层厚度偏高约 3%，在 5% 判据内可接受"。
- 为什么：四要素缺一则局限要么变成免责声明，要么变成二次建模。

### 8.6 数字纪律
- 怎么做：数字只在支撑论点时出现在正文；中间量（迭代过程、逐点数据）进表格或附录。

### 8.7 每问"模型总结"收束段
- 怎么做：每个问题的模型节末尾给 2-4 句收束（可加粗编号），回答三问：本问建了什么模型、答案是多少、凭什么可信（验证证据一句）；评委翻到任意位置都能捡到该问底线。
- 为什么：2025 优秀论文 B060（每问"模型总结"小节）与 C023（章末"N.6 结论"）的共同结构；验证充分但结论散在长段里等于没写。
