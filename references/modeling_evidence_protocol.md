# 建模与证据协议

只执行当前决策需要的部分，复用子问卡、真源和 evidence_ledger，不重复生成同义表格。现有 check_gate 不会自动理解公式和正文；本协议需要执行者和复核者检查真实产物。

## Stage 2：答题对象和义务

先判别描述、解释、预测、评价、优化、验证。非优化任务用指标、估计对象、机制关系或验证判据，不强设最大化目标。变量只列必要量。

边界查之外加**权利查**：题面给了哪些改变问题难度的权利（可换/可补数据集、可选源域、任选作答点、口径自选），逐条登记用或不用及理由；不用的权利要有明确驳回依据，不得默认放弃。例：题面允许换同分布公开数据集时，"自含数据够用"不是驳回理由——要回答换数据是否能在数据层消掉难点（如转速/工况对齐）。

在 `真源.md` 保留一份权威答题义务表：稳定 ID、题面位置、最小输出、范围/单位/时间/固定输入、验收证据、状态、缺口。状态为 `unstarted / partial / verified`；verified 只针对声明范围，不等于全题完成。不能靠改写义务抹掉欠项。

义务表同时镜像到 `decision_log.stages["2"].obligations`：`[{"id", "statement", "min_output", "status", "gap"}]`（status 同上述三态）。`check_gate.py --gate 5/8` 会校验该镜像：unstarted 拦截，partial 放行但提示 stage 8/9 如实披露。真源.md 是权威全文，decision_log 是门禁可读的镜像，两者状态必须一致。

Stage 5 补数学定义、正式函数、结果和验证文件；Stage 8 补正文/图表位置。有产物未核验记 partial；输入或实现变化后相关验证需重新确认。试点可带缺口移交，不能写已全部回答。

跨问依赖由题面决定：要求复用则复用；固定输入则独立；未说明时核对统计单位、时段、观测/预测信息可用性与机制需要，写明依据，不因复用显得高级而串接。

## Stage 3：定义与组合

对核心概念列出 `原始数据 -> 物理/统计状态 -> 指标 -> 可支持结论`。构造能刷高分却违背题意，或代理相同而真实概念不同的反例。数据无法区分时补信息、声明情景或降低结论，不能把代理改名为真值。

从当前可行的方案或清晰的题面机制出发，用本题缺口说明新增模块；缺口未观察到时标为待验证假设。对可能改变结论的主要假设，优先寻找实质不同的检验方式或替代解释；若题面、数据、资源或时间不足以形成有效替代，记录限制和未验证风险，不把未比较的路线写成已排除。数学模型与求解器分列，同一模型更换算法不冒充不同机制。

新增模块说明输入/输出、单位、边界、接收方和待修复缺口，检查重复计量与信息泄漏；需要模块归因时按 `references/experiment_cycle.md` 补关键控制，不强制逐模块穷举消融。名称只反映真实公式与实现，不强加改进词。

选型原型只证明原型；正式实现不同就重新运行关键反例，不能以较理想的玩具算法替生产实现验收。候选研究动作与完成范围见 `references/stage_03_model_selection.md`，训练及比较权限见 `references/experiment_cycle.md`。

## Stage 5：正式实现与对照

优先检查会改变答案的目标错位、边界不可行、单位/时间增量、接口错接、离散化依赖、评价权限不同。负荷影子价格必须乘实际对应的负荷增量，核对局部适用性，不机械套案例。

对可能改变选型结论的机制，执行少量真实函数探针并注明覆盖范围：例如对齐损失是否参与反向传播，无适配基线是否更新目标统计，标准化是否只拟合训练数据，表示是否覆盖声称频带，指标分母及文件/种子聚合是否一致。直接迁移与使用无标签目标统计的适配分列。复用现有实验日志和结果，不为所有任务增加全套软件测试；字段存在或脚本运行成功不代表实现语义正确。

正文控制方程与生产代码离散形式必须是同一个方程：每条控制方程与其在求解代码中的离散对象逐条对照——公式形式（守恒/非守恒）、系数位置（导数内/外）、边界项系数链，与代码实际组装的通量一致。实测教训：正文写非守恒形式而代码离散守恒通量时，变系数下两者差一个系数梯度项，正文与代码就不是同一个方程，拖到终审才发现是全链最贵的返工。有控制方程的 Qi 在验证时将对应关系记入现有验证记录；复杂离散实现可单列 `results/Q{i}_formula_code_map.md`，作为该问 L1"数学严谨性"的 evidence：

| 正文公式编号 | 公式形式（守恒/非守恒） | 代码函数（文件:函数） | 代码组装形式 | 一致性 |
|---|---|---|---|---|
| `式(<编号>)` | 守恒（变系数在导数内）或非守恒（另写明系数梯度项） | `<Qi求解脚本>:<组装界面通量的函数>` | 界面通量离散式与系数链（逐项对齐） | ✓ / ✗ |

判定口径三条：① **变系数位置**——依据题目的控制方程选择守恒或非守恒形式，并说明转换产生的系数梯度项；正文写 D·∂ξ 而代码组装 ∂(D·ξ)，两者不是同一个方程。② **边界项系数链**——边界条件中的系数因子（如坐标变换引入的 1/r_s）逐项与代码组装的边界通量对上，不允许"正文有、代码吞掉"或反之。③ **不一致即改**——发现不一致当场改公式或改代码（二选一并记录到对照表），不允许"正文一个方程、代码另一个方程"带着走。无控制方程的 Qi 不建该表，按其实际目标、约束或统计定义核验。

涉及筛选/构造数据集的义务（如"筛选部分数据组成数据集"）：筛选准则必须**面向下游任务给定量依据**（与目标域的分布距离、信噪比、带宽/频率覆盖、机理对应性），禁止只按规则筛而不论证。筛选前后各做一次分布或机理对比落盘。

涉及"信号是否够用"的环节（降噪/增强/重构类机制）：先证明简单基线在原始数据上何处失效（量化失效），再引入机制，最后闭环验证机制补上了该失效。失效→修复→闭环三步缺一，模块必要性不成立。

无真值标定/预测类义务（如目标域分类标定）：某一合法类别零预测时复核训练覆盖、类别混杂、阈值与可能的模型失败；目标数据也可能确实不含该类，不能强制补齐类别、用历史预测作真值或按预期数量调标签。已确认的实现错误先修复；信息不足时带具体不确定性和局限交付，不把零预测本身判作错误。**机理冲突升级路径**——机理证据（如理论特征频率）与模型标签冲突达到预先声明的阈值时，必须升级处理（推翻标签/降级置信/请求人工复核），不允许只标注冲突不处理；对齐度量（MMD/A-distance）改善不等于标定正确，两者分开报告。

对照锁定输入、可行域、资源预算、权限与评价定义。研究单模块时只改变该模块；算法对照允许不同搜索过程，但固定预算与可行域。多处同时修改要标联合改造，不单独归因。

状态、可行性、性能分开。可行但未证最优可以报告；超时、infeasible、unknown 不可伪装最优。基线先验可行。相同、负收益和未收敛是合法观察，不以预期改善作为通过条件。不能只用优化的代理证明现实有效性。

敏感性区分固定方案换参数评价与每情景重新决策，同时看选择变化和相对情景内最佳方案的损失。不同定义的目标值不横比。假设改变会影响决策时应重新求解，不只重算旧方案。

## Stage 8：证据约束写作

直接读取结果，核对单位、分母、时段、划分、区间水平、对照权限。trace_claims 检查链条，不替代语义核对。

| 主张 | 对应证据 | 不足时 |
|---|---|---|
| 收敛 | 预先判据、实际轨迹、状态 | 预算内返回历史最好方案，披露未收敛 |
| 最优 | 当前问题有效的状态、界/证书、容差 | 可行解、候选集内最佳或启发式解 |
| 提升 | 同口径基线、范围；随机实验需重复与不确定性 | 指定样本观察，不写普遍优势 |
| 稳健 | 有依据的扰动、选择与决策损失 | 仅对已测情景成立 |
| 泛化/现实有效 | 独立对象、标签或外部验证及范围 | 合成正确性或代理模型内结果 |

每问按难点、定义、建模决定、结果、检验、明确答案组织。核心图展示决定性证据与失败边界，不靠数量或算法通识充实内容。未完成义务如实说明，不能进入已全部解决的摘要。

**章节草稿卡与证据账本（write-as-you-solve）**：每问验证通过后立即写该问草稿卡 `paper_workspace/sections/q{i}_draft.md`（此时求解上下文最新鲜，拖到写作期会丢细节、出口径漂移）。草稿卡五件：① 模型段（目标式 + 约束 + "式中:"解释块骨架）；② 求解段（算法 + 关键参数赋值及依据 + 停止条件）；③ 结果段（分组定量结果带单位 + 运行时间/规模 + 成立条件 + 同口径横向对照表与关键模块消融）；④ 图注草稿（图前引导句 + 图后解读句：看见什么→支持什么→不能推出什么）；⑤ 移交句（本问给下一问的中间量清单）。长度由内容决定；数字必须引用已冻结数字，禁止手抄。同时向 `state/evidence_ledger.json` 追加一行：`question` / `model` / `result` / `figure` / `validation` / `abstract_claim`（可先空）/ `evidence_ids`（结果与代码文件路径，供人工回查与打包核验）。该文件是 stage 8 paper_plan 的 evidence_ledger 子集，`scripts/trace_claims.py` 两种输入均可消费——短程或中断的运行也能被证据链审计。

**摘要的文体纪律（候选版）**：摘要是成果陈述，不是实验日志。每问按"方法链 → 头条数字 → 一句验证"组织；负面结果、失败路线、存疑清单、消融细节进正文结果节与局限节，不在摘要陈列。摘要里的诚实 = 不宣称没有的东西（如无目标域真值则不写准确率、未完成义务不写已完成）+ 用一句边界句交代置信性质（如"标签置信依赖方法投票与机理核验"），而不是把"按预案弃用/无增量/存疑 N 个"写进摘要。禁止两个极端：堆失败清单，或学某些论文写无证据的"显著提升/准确分类"。
