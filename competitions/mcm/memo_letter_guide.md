# MCM/ICM Memo 与 Letter 写作指南（v7.5.0 新增）

> 服务 D/E/F 题的非技术交付物: Memo（提交给利益相关方的备忘录）与 Letter（政策建议信）。
> 与 `abstract_template.md` 分工: 该文件给**英文骨架模板**, 本文件给**框架与写作纪律**——先读本文件定框架, 再套该文件 §B 模板落英文。
> 英文句式素材: `phrase_bank.md` §9; 反面清单: `anti_patterns.md` B 类（B1 术语泄漏 / B2 建议不可执行 / B3 缺 caveat）。

---

## 1. 什么时候写哪个

| 交付物 | 题面出现 | 篇幅 | 受众姿态 |
|---|---|---|---|
| Memo | "prepare a memo …" / 面向机构内部的备忘要求 | ≤2 页 | 内部参谋向上汇报, 可稍多背景 |
| Letter | "write a letter to …" / 面向外部的建议要求 | ≤1 页 | 外部致函, 语气更正式克制 |

题面两者都出现时**分开写两份**, 不合并——Memo 给细节, Letter 只留结论与呼吁。

## 2. Memo 框架

抬头四行 + 六段:

```
MEMORANDUM

Date:    February X, 2026
To:      <职位/机构, 按题面指定>
From:    Team #XXXX
Subject: <一句话说清议题与建议方向>

1. Introduction      — 为什么写: 面临什么决策, 本文分析覆盖什么范围
2. Executive Summary — 三句内给结论: 我们建议做什么, 预期效果多大
3. Model Overview    — 用生活类比讲方法, 不出现任何模型名/算法名
4. Key Findings      — 2-4 条带数据的发现, 每条一行
5. Recommendations   — 编号建议, 一条建议一行, 每条带预期影响
6. Limitations       — 假设与失效条件: 什么情况下需要重新讨论
```

六段逐段写法（每段的唯一任务）:

| 段 | 任务 | 不许出现 |
|---|---|---|
| Introduction | 把决策背景与范围说清, 让收件人知道这与他有关 | 分析过程的流水账 |
| Executive Summary | 收件人只读这一段也能拍板 | 任何新信息（本段不引入前文没有的结论） |
| Model Overview | 一个生活类比讲清"我们怎么算的" | 模型名、算法名、符号、公式 |
| Key Findings | 每条发现一行一个数字, 只报与决策相关者 | 技术口径、置信区间细节 |
| Recommendations | 每条 = 动词开头的行动 + 预期影响 | 模糊动词（"加强""重视"）与多动作长句 |
| Limitations | 给出"什么情况发生就该重新讨论"的触发条件 | 自我贬低式罗列弱点 |

写作原则（逐条自查）:

1. **零公式**: 不出现数学符号、模型名、算法名（Lagrangian / convergence / NSGA-II 一律不许出现, 呼应 anti_patterns B1）。
2. **量化但口语化**: 每条发现和建议带数字（"减少约 18% 的等待时间"）, 但用口语单位与比较级, 不写置信区间与技术口径。
3. **一条建议一行**: 建议句 = 动词开头 + 对象 + 预期影响, 不在一行里塞两个动作。
4. **≤2 页**: 超页先删 Model Overview, 再合并 Key Findings; Recommendations 与 Limitations 不许删。

## 3. 受众差异表

同一份分析, 收件人不同则语气与深度不同:

| 受众 | 语气 | 深度 | 数字呈现 | 侧重 |
|---|---|---|---|---|
| 政府官员 / 机构决策者 | 正式、直接, 先结论 | 只要结果与行动项 | 整数化的量级 + 对比（"约 3 倍"） | 建议 5 段最重, 每条给执行抓手 |
| 委员会 / 评审组 | 中性、论证感 | 可保留方法类比与敏感性 | 保留区间与前提条件 | Limitations 加权, 显式给失效条件 |
| 公众 / 媒体 | 平易、共情, 讲影响 | 全部背景化, 无任何技术细节 | 生活化换算（"相当于每个家庭每年…"） | Key Findings 讲故事, 建议讲共同收益 |

判断规则: 题面写明收件人身份, 按身份选行; 未写明时默认"政府官员"行, 并在 Introduction 用一句 "This memo is prepared for …" 显式声明假设的收件人。

## 4. Letter 框架

四段, ≤1 页:

| 段 | 内容 | 要点 |
|---|---|---|
| 1 背景 | 我们是谁、分析了什么问题、为何与收件人相关 | 两句内, 不铺垫 |
| 2 关键发现（带数据） | 2-3 条发现, 每条一个数字 | 只留最硬的数字, 删技术前提 |
| 3 建议呼吁 | 3 个以内的编号行动项 + 各自预期效果 | action verb 开头; 呼应 phrase_bank §9 anchors |
| 4 总结 | 一句重申核心建议 + 愿意进一步沟通 | 落款 Team #Control Number |

Letter 红线: 超过 1 页、无编号行动项、无 caveat（第 3 段后带一句"若 X 发生应重新评估"）、出现正文小节编号或引文标记。

## 5. 与 Stage 8 写作流程的挂接

1. Stage 8 排章节时, D/E/F 题在论文骨架后并列排 Memo/Letter 独立写作任务, 不与 Summary 混写（Summary 250-350 词面向评委; Memo/Letter 面向题面角色, 两套受众不通用）。
2. 素材取自 `evidence_ledger` 已闭环的主张: Memo/Letter 里出现的**每个数字**必须能在正文找到同一数值的 frozen 来源, 不另算新数。
3. 成稿后自查顺序: 本文件 §2 原则四条 → `anti_patterns.md` B1-B3 → `phrase_bank.md` §9 anchor 命中（Letter 5 anchor ≥4 才 pass, 同 abstract_template §B 口径）。
4. 页数与词长只按题面当年要求执行; 题面无要求时用本文件上限（Memo ≤2 页, Letter ≤1 页）。
