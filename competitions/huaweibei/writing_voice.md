# 研究生赛写作语气 · 公式 · 推导 · 结果分析 · 结论专项指南（v2.0.0 新增, v2.2.0 扩容）

> 证据来源（v2.2.0 扩容）：2021 年数模之星提名 12 篇深读（初版引其中 4 篇精读：A21102860073 相关矩阵 53 页、C21104240047 DBS 建模 42 页、E21103860005 UWB 定位 48 页、F21103560049 机组排班 63 页）+ 2025 届优秀论文选 21 篇全量深读（A4 / B3 / C5 / D2 / E3 / F4，逐篇结论见 `star_papers_deep.md` 2025 章）。本文件只迁移语气、节奏与格式结构，**引用的原句片段仅作节奏示范，禁止照抄进新论文**；历史数值一律不得迁移。

## 1. 人称与语气

| 规则 | 说明 | 反例 |
|---|---|---|
| 动作句主语用"我们"或"本文"，一篇内倾向统一 | 摘要与问题提出用"我们"推动作（设立/提出/引入/合并/构建）；全局陈述可用"本文"。提名论文中两种都出现，但从不混用"笔者/本研究/该文" | "本研究旨在……"（学位论文腔） |
| 推测必须显式标记 | 未验证的判断用"通过讨论，我们推测……""我们预期……"引出，不用断言语气 | 把猜测写成"显然可知" |
| 示意必须显式声明 | 示意图图注写清"图中……只作为示意，并不代表实际……" | 示意图数据被读者当成真实结果 |
| 价值句全文至多两处且带功能 | "具有十分重要的价值和意义"这类句子只允许出现在背景段尾或结论段尾，且前面必须有具体缺口支撑 | 每节结尾都来一句宣传 |
| 禁止 AI 腔 | 配合 `references/ai_flavor_removal.md` 十类自查；"值得注意的是""综上所述，本文"高频复现是危险信号 | "值得注意的是，……"每页一次 |

## 2. 摘要的定量密度（每问段六要素）

提名论文摘要的逐问段不是"做了什么"的流水账，而是每问固定携带六类信息，缺一类就显得空：

```text
针对问题 X，[分析动作] → 引入/构建[中间量，给名字] → 目标式或参数赋值[具体数值]
→ 求解算法[算法 + 启发信息/停止条件类型] → 分组定量结果[带单位]
→ 规模/时间/成立条件。
```

真实节奏对照（只学节奏，禁抄原句）：

- **中间量命名**：F 题提名论文摘要不写"构建了一个矩阵"，而写"构建可换航班矩阵，该矩阵包含着相应航班之间可进行更换航班处理的信息，这简化了后续模型的建立与求解"——名字 + 内容物 + 对后续的作用，三拍齐全。
- **参数赋值进摘要**：多目标权重直接给数值（"权重参数赋值为 ω₁=1000, ω₄=1, ω₇=0.001"），不写"通过合理赋权"。
- **结果分组报告**：A/B 两组数据分开报；E 题把无干扰/有干扰 × 一维/二维/三维的误差矩阵全部给出，每个数字带单位（mm）。
- **成立条件收尾**：A 题写"可在保持 99.99% 最小精度达标的条件下完成……"——结论永远挂条件。
- **运行成本**：F 题摘要报"程序运行时间为 1 分钟"——工程题的运行时间是结果的一部分。

反模式（提名论文中不存在）：只写"建立了 X 模型，取得了较好效果"；结果不给单位；算法名堆砌而无中间量。

## 3. 公式呈现

| 位置 | 规则 |
|---|---|
| 摘要 | 允许每问内嵌 1 个核心目标式或约束式（如 min C、ρ(W)>0.99 直接写进句子），**不编号**；推导式不进摘要 |
| 正文 | 公式统一编号；式前必须有引导句（"以……为目标、以……为约束，建立如下模型："）；式后必须有"式中："解释块 |
| 式中解释块 | 逐项给：符号 — 现实含义 — 单位 — 在模型中的机制角色（该项控制什么，而非"提高拟合度"）；符号必须与符号表一致 |
| 参数赋值 | 赋值必须给具体数值 + 一句依据（量级差异、灵敏度结论或题面规定），禁止"取适当值" |
| 推导密度 | 关键推导给完整步骤；例行代数用"化简得""整理得"跳过；不得在正文大段推纯数学而忘记回到题面对象 |

## 3.5 推导写作（模型段的核心工序, v2.2.0 新增）

推导不是把数学搬进论文，而是"现实关系 → 式子 → 回到题面对象"的往返。33 篇深读里推导写得强的章节走同一节奏：

**四步叙事**（每个模型节至少完整走一遍）：

1. **现实关系先行**：动公式前先用一句自然语言说清"谁决定谁、受什么限制"（例：搬运总耗时由数据量、可用缓冲与互斥占用共同决定）。这句话就是后面所有式子的"翻译原文"。
2. **符号化**：把这句话里的对象逐个替换为已定义符号得到第一版式；新符号当场入符号表，不允许悬空符号。
3. **逐条翻译约束**：题面每条硬约束对应式中的一行或一项，正文与题面编号互指（约束 C3 ↔ 式(5) 第三项）。**跳译任何一条，就是评委说的"关键因素遗漏"**——2025 年 A 题四篇全部把 SPILL 计费口径逐条对齐题面，这是它们共同的及格线。
4. **回到对象收尾**：推导结束必须落回"该式刻画了[题面对象]的[机制]，求解它即回答 Q_i 的[任务]"。纯数学收尾直接跳求解是深读中实际观察到的失分写法。

**详略分级**（动笔前先给每段定级）：

- **关键步**（核心近似 / 变换 / 不等式放缩）：完整给步骤，每步带一句"为什么可以"——依据题设、依据假设 H_i、或依据引理。
- **例行步**（移项、合并、代数化简）："整理得 / 化简得"一句带过。
- **教科书内容**（标准算法流程、常见不等式）：引用 + 出处即可，整页重推零信息量还挤占篇幅（深读反例：有论文整页重推 NSGA-II 流程，评审价值为零）。

**式后三件套**（编号公式落地后的固定动作）：① "式中：" 解释块（§3）；② 量纲与数量级抽查一句（关键项量纲一致；典型取值下目标值量级为 10⁵ 级——防参数抄错）；③ 可解性/退化行为一句（可行域非空的条件；参数取极端值时式子退化为[什么]）。

**约束与目标之外**：优化类模型必须写"计费/成本口径与题面逐项对齐"一段（哪个动作按题面计多少、单位是什么）；少一类成本 = 模型直接不对，不算小错。

## 4. 解释节奏

- **中间量引入句型**（全文通用）：`[动作动词][中间量名]，该[量]包含/刻画[内容物]，[这简化/支持/约束了][下游环节]。`
- **定义式写作**：新术语逐个定义——`术语：是指由……组成，应当满足……约束。`定义后立刻配图，图注写清示意边界（F 题用"排班周期示意图/执勤示意图/任务环示意图"三图定义三个核心术语）。
- **图前图后双段**：图前一段写"为什么需要这张图、数据来自哪一步"；图后一段写"看见什么 → 支持哪个判断 → 下一步因此做什么 → 不能推出什么"。禁止"如图所示"四字收尾。
- **问题分析不是题面转述**：每问写困难、候选路线、选择依据、主要风险、验证位置、与下一问的接口（与 `distilled_structures.md` 一致）；A 题用"总体任务 / 算法指标 / 计算步骤 / 优化目标 / 工作安排"五卡式呈现问题归纳，可复用此卡片结构。

## 5. 结果分析（v2.2.0 从"结果报告"升级：报数字之外还要解释数字）

评审共识：只放结果不解释是三大扣分坑之一。结果章 = 报告规范 + 分析程序，缺第二层就是"图表堆砌"。

**报告规范**（不变）：

1. 分组、分场景、分维度报告（A 组/B 组、有干扰/无干扰、一维/二维/三维），不给单一总数字。
2. 每个数字带单位与口径（题定口径 vs 实际运行口径不一致时两个都报）。
3. 优化题同时报：主目标、代价/成本、约束余量、基线对比、最差或分层表现（与 `winning_patterns.md` §7 一致）。
4. 工程/算法题报运行时间与数据规模。
5. 结果段的数字必须能回溯到 `state/` 冻结数字或结果文件，禁止手抄（接 `workspace_protocol.md` §9）。

**分析五步**（每个主结果表后走一遍，短问可并步；33 篇深读高分结果章的公共程序）：

1. **报**：按报告规范给数字。
2. **比**：与基线/约束/题面参考值同口径比较；没有外部基线时构造内部基线（朴素策略、上一问结果、随机下界），并声明其性质。
3. **归因**：差异为什么发生，指到机制而非复述数字——高分写法是"控制变量式"的一句归因（例：搬运量下降主要来自分配规则而非算子序列，因为固定序列只换分配规则时指标几乎不变——2025 A 题四篇横评的共识句式）。归因不了就诚实写"贡献分解未做，列为局限"。
4. **分解**：把总差异拆成来源（口径差异 / 参数选择 / 数据划分 / 随机种子），并说明结论对哪个来源敏感——对应后文稳健性章的验证对象。
5. **边界**：最差 case 单独点名 + 失效条件 + 适用范围（哪组数据、哪个情景外推无效）。

**深读实证的高分动作**（可直接套用）：

- **恶化也报告并逐 case 归因**：2025 A 某篇 Q3 时间指标恶化，逐算例解释恶化原因——被深读评为诚实报告范式；只报改善藏恶化是硬伤。
- **负结果完整叙事**：2025 C 某篇发现前序模型存在数据泄漏，整段写"发现 → 修正 → 前后对比"，反而成为全文亮点。
- **验证表带统计裁决**：双模型五指标横评附 p 值/显著性列（2025 C），比裸数字横评高一档。
- **不确定性量化进结果**：补钻前后不确定性 0.52 → 0.39 的"收益式"报告（2025 C）；参数表每行附拟合误差 + 缺失比例双质量列。
- **指标口径声明**：多算法/多论文对比前先声明口径是否可比（2025 B 三篇回归/分类/双口径互不可比——自己的多模型横比同理）。

**反例**（深读实际观察到的失分写法）：只报均值掩盖最差 case；把内部验证写成现实部署效果；"结果良好 / 精度较高"无数字支撑；口径不一直接横比；每张图后只有"如图所示"。

## 6. 子问结尾与全文结论

- 子问结尾两句：`本问得到[题面输出]；在[验证条件]下，[主风险]未超过[判据]。该结果中的[中间量]将作为 Q_{i+1} 的[输入/约束/基线]。`（与 `distilled_formats.md` 子问结尾块一致）
- 全文结论逐问写"答案 — 条件 — 现实解释 — 边界"四件，不出现正文未定义的新数字、新模型。
- 评价与推广分三段写：结论 / 已验证的优缺点 / 推广所需的新数据与外部验证，不合并（`winning_patterns.md` §8）。

**结论三招**（v2.2.0 补）：

1. **呼应题问原句**：结论里每问的第一句用题面任务动词复述任务（"针对'确定最优监测布点'，本文以……"），让评委逐问对照打勾——不要自己发明一套与题面措辞脱节的总结语。
2. **未完成如实写**：没做完的子问写"在[已知条件]下本文给出[部分结果]，完整求解需要[缺的数据/方法]"。评委对诚实缺口的容忍远高于对注水的容忍。
3. **局限写成条件清单，不写检讨书**：每条局限 = 一个可指认的条件 + 满足后的改进路径（"外部真值缺失使绝对精度不可证；若获得[标注数据]，可通过[对照验证]补证"）。禁止"本文水平有限/研究尚不深入"式自贬——它不提供任何信息。

## 7. 使用方式

Stage 8 写作时：先按 `abstract_template.md` 六动作搭摘要骨架 → 用本文件 §2 检查每问六要素密度 → 按题型加载 `writing_playbook.md` 对应分册（公式/推导/结果分析的题型重点）→ 正文推导过 §3.5 → 公式过 §3 → 每图表过 §4 双段 → 结果段过 §5 分析五步 → 结论过 §6 三招 → 句子级打磨对照 `writing_examples.md` 正反例 → 交稿前跑 `references/ai_flavor_removal.md` 十类自查。评委模拟器（Stage 9）将"摘要定量密度"和"式中解释块"纳入 writing_reviewer 席位检查点。
