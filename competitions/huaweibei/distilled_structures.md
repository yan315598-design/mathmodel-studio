# 研究生赛章节结构蒸馏

## 摘要

功能：让评委在一页内恢复完整问题链。

顺序：现实缺口 -> 共同发现 -> 逐问模型闭环 -> 定量结果与验证 -> 整合与边界。

## 背景与重述

背景只保留会改变模型的事实。末句必须落到数学对象；重述负责统一输入、输出、约束、单位和评价口径。

## 问题分析

不是题面转述。每问写：困难、候选路线、选择依据、主要风险、验证、与下一问接口。

优秀结构常使用一张全局技术路线图和每问一张局部思路图，但局部图必须与正文变量一致。

## 假设

按“依据—简化—偏差—验证去向”写。高风险假设在正文验证处回指编号；结论中再次限定。

## 数据处理

必须在模型之前说明：来源、单位、缺失、异常、去重、时空对齐、标准化、训练测试划分和防泄漏规则。处理动作必须说明解决什么问题及可能损失什么信息。

## 建模正文

每问八步：动机、输入输出、变量约束、推导/算法、求解设置、中间量、结果解释、风险验证与回答。

前问的输出在后问首次使用时明确引用，避免同一变量重新定义。

## 结果

顺序：中间状态正确 -> 主结果 -> 基线 -> 约束/成本 -> 分层或最差表现 -> 现实解释。

## 验证

不要在论文末尾统一补一个“灵敏度分析”代替验证。每问先做局部风险验证，全文末再做跨问一致性、整体误差传播和极端情景。

## 结尾

- 结论：逐问回答。
- 评价：已证实的优缺点。
- 推广：新条件下需重做什么。

不能把三者混成模型名复述。
