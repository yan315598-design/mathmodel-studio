**填写规范**:

## 核验指引（每项要看官方通知里的什么）

| 规则项 | 核验时重点找 |
|---|---|
| 赛制时长 | 开赛/收卷精确时刻、时区、是否允许延期补交 |
| 页数与格式 | 页数是硬上限还是建议值、是否含附录与参考文献、指定模板版本 |
| 承诺书与匿名 | 承诺书模板版本、编号页生成方式、匿名覆盖到页眉/图例/代码注释哪一层 |
| AI 使用披露 | 是否强制披露、披露位置（附录/单独页）、格式要求 |
| 提交物与命名 | 提交通道（系统/邮箱）、附件大小上限、文件名是否含队号 |
| 摘要页要求 | 摘要是否独占页、字数区间、是否计入总页数 |

## 日期戳协议（Stage 0 与 Stage 9 强制执行）

1. Stage 0 组队选题时、Stage 9 终审资格门前，都必须重新读取本文件
2. 核对每条记录的 Last verified 与当年赛题发布日：
   - Last verified **晚于**赛题发布日 → 记录可信，按表执行
   - Last verified **早于**赛题发布日（或仍为 [待核验]）→ **强制提示用户人工核验官方规则**，核验并更新本文件后再继续
3. 文件过期时，资格门只执行不依赖当年口径的通则（匿名性、引用合规），其余项等用户核验结果
4. agent 不得代替用户"顺手填上"规则内容——没有官方来源的记录一律保持 [待核验]
5. **2026 特别条款**：赛题 09-22 发布，当前 Last verified（09-05）早于赛题发布日——上表初核口径（转载全文）与全部 [待核验] 项须在 Stage 0（最迟 09-22 当天）经研创网原文确认并更新后方可过资格门

## 与既有文件的关系

- `references/submission_checklists.md`（华为杯节）: 跨竞赛的稳定检查框架，本文件提供当年动态口径
- `competitions/huaweibei/rubric_overlay.json`: 评分侧重，不受本文件影响；奖项结构行可供校准锚讨论参考（锚本身仍为未验证假设）
- `references/stage_09_review.md`（Step 0 资格门）: 执行入口，先读本文件再过 7 条硬规则
- `references/huaweibei_battle_plan_72h.md`: 时间基线重映射见上方"赛制变更提示"

## 复用到其他竞赛

本文件模式可复制到任意竞赛: `competitions/<comp>/current_rules.md`（comp ∈ cumcm / mcm / huashubei / diangong / apmcm）。表头（规则项 / 当前记录 / Last verified / 来源）与日期戳协议原样保留，规则项按该竞赛特点增删。
