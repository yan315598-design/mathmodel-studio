# 研究生赛案例检索协议

## 目标

从 30 道历史题中检索结构相似案例，为当前题提供问题拆解、路线比较、假设风险、必要验证、图表和写作骨架。历史数值和结论禁止迁移。

## 查询字段

从当前题提取：

- 对象：矩阵、信号、网络、状态、人员、空间、医学事件等。
- 任务：预测、反演、识别、评价、调度、控制、路径、压缩、三维重构。
- 数据：时序、空间、多源、图像、事件流、表格、附件规模。
- 约束：精度、容量、依赖、实时、守恒、安全、公平或成本。
- 中间量：残差、置信度、状态、图、资源占用、风险场等。
- 主要风险：泄漏、外推、不可行、局部最优、物理失真、分辨率虚高。

## 评分公式（v2.0.0 起与 `scripts/retrieve_cumcm_cases.py` 实现严格一致）

```text
score = min(1.0, text_cosine * 0.76 + tag_overlap * 0.14 + max(base_evidence, manual_evidence) + review_bonus)
```

- `text_cosine`：查询与案例文本（标题+范式+问题本质+路线+风险+验证+图表叙事）的中文二元组 + 英文词分词，IDF 加权余弦。
- `tag_overlap`：10 类任务标签正则（优化/预测/评价/调度/仿真等）的查询-案例交集占比。
- `base_evidence`：evidence_level high=0.08 / medium=0.05 / problem_only=0。
- `manual_evidence`：reviewed_paper_count ≥3 → 0.08，=2 → 0.05，=1 → 0.03。
- `review_bonus`：人工复核通过 +0.02。同分按 reviewed_paper_count、paper_count 次序。

注意：证据加成上限 0.10，短查询文本分常 <0.1，**论文多的老题可能系统性强于论文少的新题**；使用检索结果时若命中案例与新题年份差 ≥3 年，应人工确认结构相似性而非只看总分。

题号和年份不加分。奖项只影响证据阅读优先级，不影响结构相似度。

## 运行时合并

1. 读取 `cases/index.json` 得到 30 题基础候选。
2. 以 `cases/manual_review_annotations.json` 覆盖标题、范式、逐问依赖、路线、风险、验证、图表和写作字段。
3. 输出前 3—5 个候选，每个说明相似点、关键差异和不可迁移内容。
4. 若读取 `papers/manual_paper_reviews.json`，只在需要写作或图表结构时返回提名论文对应段落，不用其历史结果指导新题数值。

## 输出格式

```text
案例：
相似结构：
可借用的逻辑：
必须重做：
主要风险与验证：
证据 ID：
```

## 边界

- 单篇路线标 `single_paper_route`，至少两篇支持才可写 `cross_paper_consensus`。
- 2022—2025 的优秀论文统一为 `not_locally_identified`，不推测数模之星。
- OCR 自动标签只作候选；人工覆盖层优先。
