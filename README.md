## 这是什么

mathmodel-studio 是用于数学建模竞赛的 AI Skill，为 Codex、Claude Code、ZCode 等助手提供工作指南、方法参考和配套脚本，协助完成审题、模型选择、代码求解、结果检查和论文整理。

你可以从一道完整题目开始，也可以只检查一段代码、画一张图或修改一节论文。关键模型路线和逐问结果需要你确认；工作记录保存在本地，保留这些文件后可以在新会话中继续。助手能否读取文件、运行代码和导出文档，取决于所用平台的能力、工具权限和本地环境。

Skill 里装的是规则、经验库和模板，不含题目答案，也不含别人的论文成品。

## 能帮什么

| 你的需要 | 它给出的东西 |
|---|---|
| 决定做哪道题 | 候选题对比矩阵：考查要点、主要风险、与历年题的相似度、适配队伍的评估 |
| 读懂题、拆问题 | 审题四查（边界 / 权利 / 目标 / 假设）+ 义务清单 + 每问的候选模型路线 |
| 定模型、要依据 | 候选短名单、推荐项及理由、文献来源、方法失效的边界，并落成一份《选型总表》 |
| 把题解出来 | 每问按"建模 → 求解 → 验证 → 解释"循环推进，验证通过才写进论文草稿 |
| 画图、检查图 | 数据图由代码生成并自动检查文字重叠、越界；示意图给可编辑源文件再人工精修 |
| 写论文、交论文 | 按对应竞赛的写作范式组装正文与摘要，提交前模拟评委打分，并核对数字、图表、参考文献 |

## 安装

先说版本：需要 Python 3.10 或更高（本轮的验证环境是 Windows + Python 3.13.9）。Pandoc、Word 或 LibreOffice、TeX Live 或 MiKTeX、中文字体属于系统软件，要另外装，见下面"环境"一节。

选你正在用的宿主，把仓库克隆到对应目录：

```bash
# Codex / 通用 agents 目录
git clone https://github.com/yan315598-design/mathmodel-studio.git ~/.agents/skills/mathmodel-studio

# Claude Code
git clone https://github.com/yan315598-design/mathmodel-studio.git ~/.claude/skills/mathmodel-studio

# ZCode
git clone https://github.com/yan315598-design/mathmodel-studio.git ~/.zcode/skills/mathmodel-studio
```

以上命令适用于目标目录尚不存在的首次安装。也可以在仓库页面点击 Code → Download ZIP，解压后将文件夹命名为 mathmodel-studio，放入对应的 skills 目录；确认 SKILL.md 直接位于其中。安装后重新打开会话或刷新 Skill 列表。

在准备使用的 Python 环境中，按安装位置选择一条命令，一次安装常用建模与文档依赖；多个助手共用同一个 Python 环境时不必重复安装：

```bash
# Codex
python -m pip install -r "$HOME/.agents/skills/mathmodel-studio/templates/shared/requirements.txt"

# Claude Code
python -m pip install -r "$HOME/.claude/skills/mathmodel-studio/templates/shared/requirements.txt"

# ZCode
python -m pip install -r "$HOME/.zcode/skills/mathmodel-studio/templates/shared/requirements.txt"
```

以上为 Bash / Git Bash 写法，其他终端可将引号内路径替换为实际完整路径。依赖文件已包含 python-docx、pymupdf 和仅 Windows 生效的 pywin32，以及常用计算、优化、机器学习、仿真和绘图库。部分专用模型、商业求解器或可选图形功能仍可能需要额外依赖；安装报错应先处理，不能把部分成功视为环境已就绪。

## 环境：哪些要另外装

| 组件 | 用途 | 缺失时 |
|---|---|---|
| Pandoc | Markdown 转 LaTeX / Word | 转 tex 有降级回退；导出 Word 审阅件会失败 |
| Word 或 LibreOffice | Word 转 PDF | 出不了 Word 链的 PDF |
| TeX Live 或 MiKTeX（xelatex） | 编译 LaTeX 出 PDF | 走 LaTeX 链时无法生成 PDF |
| 中文字体 | 中文论文渲染 | 中文可能显示异常 |
| MILP 求解器 | 整数规划类题目 | 常用求解器缺失时相应题型受限 |

这些系统工具不包含在 pip 安装中。Word 和 LaTeX 是两条成稿路径，按需要配置即可；希望两条路径都可用时，再准备完整环境。安装后可以对助手说：

```text
请使用数模工坊，确认 Skill 已加载。
检查 Python、绘图依赖、Pandoc、文档转换工具和中文字体是否可用。
列出可用项、缺失项和未执行的检查，先不要安装软件或修改系统配置。
```

## 第一次用它：审题、选型、求解

1. **审题。** 说"开始建模"。它会一次问齐五件事——竞赛（华为杯 / 华数杯 / 国赛 / 美赛 / 电工杯 / 亚太杯）、题号、队员人数与分工、截止时间、题目 PDF 路径。题目没公布就回"未公布"，之后补上。接着进入审题：四查（边界 / 权利 / 目标 / 假设）把题面要求整理成义务清单，交你确认。
2. **选型。** 说"这道题每一问该用什么模型"。它给出每问的候选模型与算法、推荐项、依据、文献来源和方法失效的边界，由你拍板；拍板结果落成《选型总表》，随时可以翻看。
3. **求解。** 说"帮我解第一问"。若还没有选型记录，它会先补一份选择卡；然后按"建模 → 求解 → 验证 → 解释"推进，把结果和验证证据交你审阅，确认后再进下一问。

## 完整流程

| 阶段 | 它做什么 | 你做什么 |
|---|---|---|
| 赛前兵检 | 检查环境与依赖，搭好工作区骨架 | 按报告补装缺的软件 |
| 一、备战与选题 | 把候选题做成对比矩阵：考查要点、风险、与历年题的相似度、胜算评估 | 审阅矩阵，选定题目 |
| 二、审题与选型 | 审题四查、义务清单；为每问列候选模型路线，附假设与验证方法 | 拍板每问的主路线 |
| 三、建模与求解 | 每问按"建模 → 求解 → 验证 → 解释"推进，通过后写成论文草稿卡；另做全局灵敏度与稳健性 | 审阅每问结果与验证证据 |
| 四、写作成稿 | 把草稿卡组装成正文，写模型评价，摘要按三遍制打磨 | 在你的编辑器里改细节 |
| 五、终审提交 | 模拟评委评审并给扣分清单；数字对账、图表与符号一致性检查；按清单打包 | 按清单修改，确认打包 |

每个阶段收尾都会自评并给出结论，不达标就返修，不会硬推进；遇到卡壳时它会给出"已试过什么、当前最好结果、下一步选项"交你决定，而不是编一个结论。

## 也可以只用一部分

| 你说 | 它做 |
|---|---|
| "帮我复核这段求解代码" | 重跑脚本本身，报退出码、数值范围、约束是否被违反，不轻信转述 |
| "给第三问画一张灵敏度图" | 说清数据和要支撑的结论即可出图，出图后自动过一遍图面检查 |
| "写摘要" / "润色问题分析" | 按对应竞赛的写作结构只写这一节，不启动完整流程 |
| "继续上次的进度" | 读工作目录里的进度文件，从断点接着做 |

表中的独立局部任务（单节的写作 / 绘图 / 代码复核）不建进度文件，做完即止；"继续上次的进度"不在此列——它按工作目录里已有的进度记录恢复，不另起新文件。

## 支持的竞赛

| 竞赛 | 时长 | 语言 | 知识库深度 |
|---|---|---|---|
| 研究生赛（华为杯） | 100h | 中文 | 较深：2021—2025 年 30 道题，190 篇优秀论文入库（其中 12 篇提名奖与 2025 届 21 篇逐篇深读），另有六域动作手册 |
| CUMCM 国赛 | 72h | 中文 | 较深：2023—2025 年 33 篇可核验论文、25 个题面案例、五域动作手册 |
| 华数杯 | 72h | 中文 | 部分：六届 18 道赛题 + 18 篇优秀论文，按国一标准蒸馏 |
| APMCM 亚太杯中文赛 | 72h | 中文 | 部分：2024 / 2025 年 6 份赛题 + 12 篇优秀论文 |
| MCM / ICM 美赛 | 96h | English | 早期：按公开评审标准与公开教材共识整理，未做论文实测统计 |
| 电工杯 | 72h | 中文 | 早期：按历年题量与公开评审标准估算 |

六个竞赛的题目、数据、模板和经验统计互相隔离，不会拿一个比赛的结论冒充另一个比赛的。标为"早期"的两个赛事，输出会带提示，结论确定性降一档。华为杯与华数杯名字接近，是两个独立分支，不会混用。

## 论文怎么写出来

Markdown 是内容的唯一真源，正式文件从它导出；导出链在写作期由你选定，选定后不擅自切换：

```text
Markdown 真源 ──→ LaTeX → PDF
              └─→ Word（有限呈现编辑）→ PDF
```

真源就是普通的 Markdown 文件，你可以用 Obsidian、VS Code 之类的编辑器直接改。论文里的数字与来源文件绑定：定稿数字会记下它来自哪个结果文件，回头核对时如果来源变了会被发现，但不会自动重算或改写你的论文；图表和摘要引用的是同一批数字，改数字要走回源流程，只改 Word 或 LaTeX 派生稿不算数。Word 链路只用于呈现层的有限编辑（编号、版式这类），正文内容仍以 Markdown 为准。数学字体按你选定的政策走，不会被悄悄改成全局正体或全斜体。缺编译器或字体时它会明确报错，结构检查不能代替渲染验收。

## 使用边界

- 关键决策由你拍板：选哪道题、每问走哪条模型路线、终稿是否确认，它不会替你决定，也不会跳过这些节点。
- 文献检索等在线功能需要网络和服务可用性；检索到的来源及其与题目的关系仍需核对。
- 美赛和电工杯目前是早期版本，不适合把它们当稳定经验使用；华数杯和亚太杯的实测数据分别来自 18 篇、12 篇论文，只用于校准，不是官方评审门槛。
- 缺依赖、缺软件、没跑过的检查，都会如实写成"未测 / 缺依赖"，不会写成"已通过"。
- 它不会替你把论文变好，也不替你承担判断；成绩取决于题目、数据和你自己的取舍。
- 打包只是按当年竞赛要求生成提交件与校验和，不等于向赛事平台提交。

## 更新

更新前先看状态，再拉取，避免覆盖本地改动：

```bash
cd ~/.agents/skills/mathmodel-studio   # 或 .claude/skills、.zcode/skills 下的同名目录
git status                             # 确认工作区没有未提交改动
git pull --ff-only                     # 只做快进更新
```

如果 git status 显示你动过文件，先备份或提交再更新。依赖清单有变化时，更新后按安装一节的方式重跑一次 pip 安装。
